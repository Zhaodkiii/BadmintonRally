# 晚风球社 · BadmintonRally

iPhone 横屏羽毛球单打。玩家握手机朝电视挥拍，角色自动跑位。应用支持通过系统屏幕镜像投屏，也提供独立的触屏玩法。当前可玩版本使用 SwiftUI Canvas 实时绘制球场、人物、球拍和球路。

Mac 客户端仅用于开发采集：同步整理 iPhone 运动数据和现场录像，供后续离线训练使用。正式游戏在 iPhone 上独立运行。数据归档格式、标注及交接要求见[《Mac 动作采集工作台需求》](docs/Mac动作采集工作台需求.md)。

## Mac 开发采集怎么用

Mac 运行 **RallyCapture → My Mac**，iPhone 打开首页的 **Mac 联合采集**。两端使用同一局域网；蓝牙用于交换连接信息。采集页面的动作列表、人物、左右手动画及分步说明共用一份实现。

1. **连接。** Mac 点「连接 iPhone」开启配对；手机点「查找附近的 Mac」，选择主机。核对两端数字，在 Mac 允许。无法用蓝牙时，展开两端的局域网密钥选项。同一拍只需配对一次，后续动作沿用连接。
2. **准备。** Mac 左栏选择保存目录和摄像头、开启预览、填写参与者与持机手。正对相机，确认双肩与持机手腕入镜。两端任选一端切换「本次动作」，另一端随即显示相同示范。一次采集对应一种训练动作。
3. **逐拍校准。** 可先点「先看握持与校准」，看持机手从下方托住手机、拇指搭边以及四步位置动画。每步都能暂停在目标姿势。点「开始本次校准」即开始保存原片和 IMU。依次在胸前屏幕朝上、向持拍侧伸臂并转动机顶、向前上方伸臂并抬起机顶、回到胸前。每个位置保持约一秒。程序检查静止窗口、机身方向与画面中手腕相对双肩的位置；前上方检查抬高和机身仰角。侧伸、回位均与个人胸前基准比较。被遮挡时 Mac 操作者可以目视核对位置；姿态和静止仍须通过。每次重录或换动作都重新建立基准。
4. **开始与结束。** 四步通过后进入待录。在 iPhone 点「确认开始采集」，看到正在采集后开始挥拍。收拍回位后，在 iPhone 点「确认结束并保存」。Mac 显示当前状态和录像。录像中断时，手机运动数据继续保存，手动结束后场次标为部分记录。数据由 Mac 统一归档，重连后手机获取当前阶段。每拍目录内 position_targets.json 保存目标阈值（二维距离以肩宽为单位），calibration.jsonl 保存实际姿态、窗口时间、手腕位置及证据来源；action_window.json 标记正式动作区间。原片和 samples.csv 都包含校准过程。当前校准提示的变化也写入事件轨，复核时可定位卡在哪一步。
5. **复核。** 点「复核本拍」，或在「记录 → 打开场次复核」打开已存目录。核对视频、角速度与提示/识别事件后保存人工标签。正式动作区间是操作者划分的窗口，训练标签仍以复核为准。
6. 点「导出训练包」选择目标目录。每次导出创建独立快照，含相对路径、原始样本、视频和帧时间、校准/时钟记录、标签版本、质量信息及 SHA-256 清单。另一台电脑使用 Python 3.11+ 可直接检查与提取：

```sh
python3 Tools/check_capture.py /path/to/exported-dataset
python3 Tools/check_capture.py /path/to/exported-dataset --trial TRIAL_UUID --out swing.csv
```

两端的专项训练菜单按后场、网前、中场与接杀、发球分组。可采集高远球、扣杀、吊球、挑球、放网、推球、扑球、平抽、接杀挡网、接杀反抽和四种发球。历史场次可按动作浏览、复核和导出。新采集可选「慢速演示」或「正常实战」。历史场次的快速实战可在采集历史中筛选。联合采集时双端同步选择，校准开始后锁定。速度是采集指令，原始时间戳保留实际节奏。联合采集把 speed 写入场次清单、动作窗口和训练索引；单机采集写入运动 CSV、校准摘要及复核文件。历史场次缺少该字段时保留为空。

Mac 顶部点「采集历史」自动打开当前采集目录。可搜索参与者、动作或场次 ID，并按动作、速度、复核状态筛选。双击记录进入同步复核，校准菜单可直接跳到各步骤。按住 Command 多选，点「导出所选训练包」；每场生成独立目录与校验清单。已导出的包也可以在历史页打开预览，修改标签请打开原始场次。导入其他历史目录只影响历史页浏览。

已有手机单机采集文件可在 Mac 点「导入手机 CSV」。原始 CSV 与同目录下匹配的人工标签、特征文件一并保存，旧版试次仅使用相对时间。

样本 CSV 的角速度单位为 rad/s，加速度与重力单位为 g，姿态按 xyzw 顺序。视频以第一帧附近为回放零点，对齐使用帧 PTS、Mac host clock 和手机单调时间。实测掉帧数见 video_quality.json，超过 100 ms 的运动空洞见 quality.json。MPJPE、厘米级三维位置及视觉训练属于后续独立实验。

## 运行与试玩

用 Xcode 打开 BadmintonRally.xcodeproj，选择 BadmintonRally scheme。最低部署版本为 iOS 17。模拟器选择 iPhone 后运行，默认启用触屏。真机安装时在 Signing & Capabilities 选择自己的开发团队。

1. 初次体验选择「挥拍入门」，跟随球场提示依次完成上挑、扣杀、平抽和放网。不计比赛比分，失手后自动重试。完成后可选择「自由练习 → 高球」。触屏模式下选择落点，球进入近场时按「下挥」或「上挑」。「放网」预选下一拍，可再次点按取消。
2. 真机关闭触屏模式，按实际握法静止一秒。按提示依次上挑、下挥和平抽，每类收两拍，再各试打一拍。每拍回到原握姿稍停。九拍通过才开放体感开赛。暂停续局只需重新握稳，换手或换握法可点「重新校准」。轻挥模式可在首页设置中开启。
3. 连接电视时，在 iPhone 控制中心选择「屏幕镜像」。进入「设置 → 测量投屏延迟」，看电视上的光点穿过中线时在手机上点按。八次后可采用估算值，在开赛时打开「看电视游玩」，比赛会按补偿后的时间回查球的位置。本机模式使用零投屏补偿。
4. 快速单打以轻上挑发球。7 分制，平分须领先 2 分，9 平后下一分决胜。支持三档对手。暂停后可以继续、重发本球或提前结束。练习另有快球、左右交替和混合供球。
5. 真机验收需覆盖左右手、轻挥、连续回摆、暂停恢复及电视延迟变化。模拟器覆盖触屏操作；实际体感准确率须由独立参与者的数据测定。

## 采集、训练与接入

在首页打开「标准动作采集」，从顶部选择动作。「采集设置与文件」里可更改匿名编号和持机手、观看当前球种的 BWF 原版教学。录制中设置栏收起，保留球场、步骤和录制控制。每个专项动作都有准备、引拍、挥出和回位示范。「实际动作」里的「背景」可用于复核误录。左右手切换会镜像人物与拍头。点「分步查看」可停在单步阅读，点「连播」看完整示范。动作分解参考 [BWF Shuttle Time 教师手册](https://www.badminton.org.au/wp-content/uploads/2022/11/1.-BWF-ST-Teachers-Manual_Inclusivity_ENGLISH.pdf)，画面是手持手机时的短挥示意。

- **跟随演示**：点「开始校准」，按四步提示校准握向。通过后点「确认开始采集」，跟随动画挥拍，回位后点「确认结束并保存」。动画与 CSV 的步骤标记共用传感器相对时间，演示结束后仍会继续采集。
- **自由录制**：关闭「跟随演示录制」，完成同样的逐拍校准后，按真实节奏完成动作。手动确认起止，录制期间分批写入文件。两种模式均保留原始融合运动数据，即使候选检测器漏检也会存盘。
- **单机校准文件**：每次另存与运动 CSV 的 session 相同 UUID 的 calibration.csv 与 calibration.json，分别包含逐帧校准信号和四步结果。证据标为 phone_orientation_only。相机手腕位置核对仅在联合采集可用。
- **复核与传输**：实际完成的动作可能与提示不同。选择「实际动作」并点「确认标签」，再打开「采集设置与文件 → 已保存文件 → 分享全部到电脑」，通过系统分享面板选 AirDrop 或「存储到文件」。也可单独分享某条 CSV。历史文件保存在 App 的 Documents/MotionTrials，重新打开页面仍可分享。
- **电脑端读取**：以 session 关联文件。原始 CSV 每行一帧；t_s 是相对秒数，rx/ry/rz 为机身三轴角速度（rad/s），ax_g/ay_g/az_g 为去重力加速度（g），gx/gy/gz 为重力（g），qx/qy/qz/qw 为姿态四元数，参考系为 xArbitraryZVertical。请求频率为 100 Hz，以实际时间戳计算间隔。cue_phase 是演示提示，实际击球帧须另行标注。started_utc 对应按下录制的 UTC 时间，hardware 和 ios 给出设备与系统版本。当前文件名以 manual 或 interrupted 区分手动结束和中断。旧版的 complete 表示当时自动保存。
- **标签层级**：原始 CSV 的 prompt 是指令，review.json 的 actual_label 是人工复核的整条标签。仅在识别出一个候选时另存 accepted.csv，供现有五特征训练工具使用。历史动作的原始记录可用于独立分析。现有游戏分类器支持上挑、下挥、平抽及背景四种训练标签。训练与评估按参与者拆分，避免同一人的重复挥拍同时进入两组。

将导出的 *.accepted.csv 汇总到本地目录。初版训练工具使用标准库和五项特征，按参与者留出。下例中的目录和编号需替换成真实采集值。

```sh
python3 Tools/train_strokes.py ./samples --holdout P09 P10 --output ./StrokeModel.json
```

查看留出人员的混淆表，并单独用连续回合评估漏检、重复与延迟。需要部署时将审核后的 StrokeModel.json 放进 iPhoneApp/Resources 后重新构建。比赛与试打共用本局个人模板。可选模型和旧规则仅保留在动作采集管线中，用于离线实验。原始采集文件保存在应用 Documents/MotionTrials，单条完成后可用分享面板导出。

## 动画教学参考与动作分解

依据 BWF 教学视频的分镜预览核对站位与动作顺序，并结合 Shuttle Time 教师手册核对触球和随挥要领。人物、拍头轨迹和球路均在端上绘制。四段时间是采集提示的节奏；CSV 中的提示阶段不能直接当作运动员实际触球时间。分镜预览间隔约一至两秒，肘、腕、拍面的过渡由关键姿势插值。握法和前臂旋转的细节请结合原版示范观察。[BWF 教师手册](https://www.badminton.org.au/wp-content/uploads/2022/11/1.-BWF-ST-Teachers-Manual_Inclusivity_ENGLISH.pdf)

| 动作 | 准备与引拍 | 触球与随挥 | 原版示范 |
|---|---|---|---|
| 正手上挑 | 持拍脚向前跨，正手侧降低拍头 | 在身前低处向前上方挥，球升向后场 | [L9V3 Forehand Lift](https://www.youtube.com/watch?v=ZDfaUrR0RY0) |
| 反手挑球 | 反手位伸拍，屈肘短引 | 拇指侧引导向前上方挥出，收回身前 | [L8V3 Backhand Lift](https://www.youtube.com/watch?v=UXhneWqy0Zw) |
| 正手平抽 | 身前举拍，短引，准备快速衔接 | 身侧稍前接触，球平快飞出，迅速回拍 | [CE1M7V17 Forehand Drive](https://www.youtube.com/watch?v=hFIc77HRSiA) |
| 头顶高远 | 侧身，非持拍手上举，重心由后向前 | 伸臂在持拍肩上方稍前触球，向深远处送出并随挥 | [L13V3 Forehand Clear](https://www.youtube.com/watch?v=8QCeXig1eDE) |
| 正手扣杀 | 与高远球相似的头顶准备，蹬转引肘 | 在更靠前的高点加速，球向下，手臂继续随挥 | [L17V2 The Smash](https://www.youtube.com/watch?v=2J4V37Qf9FY) |
| 正手吊球 | 保留与头顶高远相似的引拍 | 在肩上方稍前控制送拍，球落前场，随挥较短 | [L15V3 Overhead Drop Shot](https://www.youtube.com/watch?v=z2YGlINxso4) |
| 正手网前放网 | 向网前跨步，伸拍，拍面迎球 | 在网带附近轻送，拍头位移短，蹬回准备位 | [L3V4 Introduction Net Shots](https://www.youtube.com/watch?v=TVNW9S7o0Bk) |
| 反手短发 | 身前持球，反手准备，拍头朝下 | 短引后前推，球越网后下落，收拍幅度小 | [L7V3 Backhand Short Serve](https://www.youtube.com/watch?v=RqEsdMSq7pg) |

「下挥」保留为游戏的肩旁短挥指令，「背景」用于记录自然移手。这两项显示持机示意，便于与专项教学和数据标签区分。

## 验证

Xcode 中按 ⌘U 运行模拟器操作测试。规则测试可独立运行：

```sh
swiftc iPhoneApp/Game/Rally.swift Tests/RulesChecks.swift -o /tmp/badminton-rules
/tmp/badminton-rules
```

当前人物使用程序化关节动画。美术设定稿中的逐姿态成品、真实训练集、真实电视延迟分布及上架签名仍属于后续制作与实测工作。
