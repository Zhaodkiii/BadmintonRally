# 羽毛球动作采集工作台 · macOS 与 iPhone 开发需求

2026-11-22 · 需求设计稿 · 面向 iOS/macOS、算法、动画及采集操作员。本文件记录产品目标与验收设计。已落地的采集、配对、回放、标注与导出流程见[工程使用说明](../../README.md#mac-开发采集怎么用)。当前每场独立保存一段带媒体分片的 camera.mov，批次日志按序归并为 samples.csv，具体文件以导出清单为准。文中的帧率、误差、延迟及样本量均为首轮工程目标，须用指定设备实测并随数据集版本复核。

### 当前联合采集流程

Mac 和 iPhone 共用动作目录、人物示范、当前动作与采集进度。一次专项采集依次经过选择、校准录像、四个位置检查、准备倒数、动作录像与归档。胸前为个人标准位置；侧伸、前上伸、回位记录目标与实际姿态，视频可见时核对手腕相对肩宽的二维投影。相机遮挡时人工确认位置与自动确认分别标记。取消及未通过的试次保留部分记录。训练导出保留完整视频与 IMU、校准窗口和单独的正式动作窗口。下文涉及已知尺寸标记及三维场地坐标的内容属于扩展实验。

## 1. Mac 开发工具的职责与交付

**Mac 客户端仅供开发人员在采集现场使用，交付物是一份可回放、可复核、可移交给训练程序的数据集。** iPhone 在实际游戏或专项采集过程中记录运动数据；Mac 接收数据、录制外部视角视频、对时并归档。算法人员之后使用独立的离线工具训练和评估模型，验证通过的模型随 iPhone 应用发布。玩家日常校准、比赛与动作识别均由 iPhone 独立完成。

开发者在 Mac 选择数据目录、配对 iPhone、选择摄像头。受试者先把手机放到准备位置，看到录制指示后拿起手机，按提示完成握姿与空间校准，再做指定羽毛球动作。Mac 从拿起前一直录像到收拍后，把原始运动序列、视频、时钟映射、校准、采集质量和人工标签整理到同一试次。开发者当天就能在同一时间线上拖动视频、角速度曲线和手机当时记录的识别事件，定位一拍漏检或错认的原因。

|使用模式|可用输入|可交付结果|评价依据|
|---|---|---|---|
|开发采集，第一版必须完成|iPhone IMU、Mac 单目 RGB 摄像头、人工复核|双流同步回放、手机相对朝向、可逐帧复核的握持与挥拍画面、带区间的动作标签|原始视频、传感器序列、人工事件、一致性与同步检查|

**技术边界。** 同一个人保持手机轨迹不变时，可以改变左手、膝盖甚至身体朝向。单手机无法唯一决定这些关节。一次静止校准可以估计重力方向；水平朝向需另给参考，手机绝对位置也不会因指定了一个原点就持续可测。对含小偏差的加速度做两次积分会放大误差，例如恒定 0.05 m/s² 的残差在 4 秒内就会贡献约 0.40 米的位移误差。重力扣除误差、握姿变化也会污染积分。产品目标应分成“实测手机运动”“估计持拍侧动作”“生成其余身体动画”，在回放和报告里分别标识。手持手机空挥只能标注虚拟触球代理事件；球拍实际击球、拍面方向、球速需要另外的器材和验证。

**窗口布局。** 顶栏常驻显示人、手、试次、录制红灯和目标目录。中央约三分之二是摄像头画面，默认显示原片；导入离线分析结果后可叠加关键点。底部显示角速度、加速度、姿态变化和各事件轨道，共用游标。侧栏折叠显示采样率、最大空洞、视频掉帧、对时误差、存储余量；点击告警跳到出错时刻。回放支持 0.25×、逐帧、前后一个击球事件、循环选段；侧栏可对比手机当时的预测与后续导入的离线结果。iPhone 只显示握法、当前动作、连接、录制状态，采样期间避免频繁触屏。相机预览与落盘状态分别显示，防止只看到预览就开始挥拍。

**状态机。** 空闲 → 已配对 → 通道就绪 → 预检 → 写入中（含准备、校准、动作、回位标记）→ 正在收尾 → 可回放。权限拒绝停在预检；写入期间各设备独立记录和呈现退化状态。停止优先于排队提示命令。重复 Start/Stop 使用命令 ID 去重；Mac 只接受本场次绑定的一台手机写入同一设备流。断线重连或应用重启产生新的连接代次，设备重启产生新的时钟段；均禁止默默拼成连续时轴。

## 4. 协议、时钟与视频录制

1. **数据通道。** 控制消息涵盖 hello/capabilities、选择场次、arm/ready、start/stop、校准步骤、事件和错误。样本批含 schema_version、设备/场次/流 ID、连接代次、first_seq、count、每帧源时间及传感器值。建议首测每 5 帧或 40 ms 先到即发，实测后调节。在本地追加日志成功后才能回收重发缓存；Mac 持久化后回 ACK 已连续写入序号及缺口。按流 ID 与序号幂等合并。不能用渲染频率限速采集。实时图可抽点，原始文件保留全量。
2. **时钟域。** iPhone 使用 Core Motion 单调时间；Mac 选择统一 host clock。UTC 仅用于场次检索。传感器采样、网络到达、显示刷新和视频曝光具有不同时间意义。会话两端以 ping 四时间戳反复采样：Mac 发 m0，手机收 p1、发 p2，Mac 收 m3；配对中点 (p1+p2)/2 与 (m0+m3)/2。以扣除手机处理时间的往返时长筛掉拥塞轮次，用低延迟样本拟合 m = a·p + b，记录漂移、残差、RTT 及拟合有效区间。启动建议连续 20 轮，随后每 5 秒复测，休眠、重连重拟合。单向时延不对称会使中点偏置，低残差不能独立证明绝对同步准确。
3. **视频时间。** 建议用 AVCaptureSession、AVCaptureVideoDataOutput 和 AVAssetWriter。以采集样本的 CMSampleBuffer PTS 写视频；记录原始 CMTime 的 value、timescale 与视频轨道零点。确认设备时钟与 session/host 的关系，显式转换并保留映射。独立串行队列写媒体，推理和 UI 不阻塞录像。以实际协商格式启动，优先试 1080p60，紧张时明确选择 720p60 或 1080p30。逐帧记录捕获与成功写入情况，不用 frame_index / 标称 fps 代替 PTS。外接相机和 Continuity Camera 要单独验证延迟；参与采集的 iPhone 不同时充当外部参考相机。[Apple 视频输出](https://developer.apple.com/documentation/avfoundation/avcapturevideodataoutput) · [Apple Core Media 时钟](https://developer.apple.com/documentation/coremedia/cmclock)
4. **物理同步检查。** 每段开始和结束做三次短促、清晰且被相机看到的机身往复转动，中间留不同间隔；有标记时从画面估计标记的方向变化率，对照 IMU 角速度。可再用由同一时基记录发光事件的可见闪光作独立验证，单纯记录 UI 请求点亮的时刻不足以确定实际发光。将误差写成区间，30 fps 一帧约 33 ms，60 fps 约 17 ms；人工只能给出一帧或数帧范围时，按该范围评估，不虚报毫秒真值。
5. **存储与隐私。** Mac 首次选择目录可用 NSOpenPanel；沙盒版保存 security-scoped bookmark，失效时要求重选。启动前验证相机权限、蓝牙和本地网络权限、可写磁盘及剩余空间；按所选沙盒配置声明相机、网络和用户选择文件权限。默认关闭麦克风，采集前显示录像范围和用途，默认本地存储，操作员显式导出视频。建议用匿名 ID 保存数据，同意记录及身份对照表另存。按 8 Mb/s 估算，半小时视频约 1.8 GB，另留临时封装及余量；以实际码率更新剩余时间。录制时相机断开、磁盘满或写入失败，立即提示并记录最后成功点。长场次按可单独打开的短片段封装；启动时扫描未关闭的会话，尽量恢复至最后已封装片段并标 partial。

## 5. 初始空间、握持与指定位置校准

定义 D 为手机机身轴，I 为 Core Motion 启动时的参考系，C 为相机光学系，W 为场地系，H 为虚拟握柄。建议 W 原点取地面胶带十字中心，+Y 向上，+Z 从选手指向球网，+X = +Y × +Z，采用右手系、米和弧度。参与者面对球网时左右落点以场地图示明确标出。约定 T_A←B 把 B 中的点变换到 A；区分点的刚体变换和方向的纯旋转。实现层明确相机图像 y 向下、视频旋转和镜像；预览镜像不改动原始坐标。每条变换标明来源、有效期及误差。为四元数明确分量顺序 xyzw、主动/被动旋转以及乘法顺序，使用实体手机绕各轴转 90° 的记录作测试样例。[Apple 设备运动](https://developer.apple.com/documentation/coremotion/cmdevicemotion)

|步骤|场地与用户动作|如何测量和放行|何时重做|
|---|---|---|---|
|A 相机内参与场地|固定机位与焦距，空间实验使用实测格长的 ChArUco 板，多角度拍摄；板在场地上的位置和朝向有测量记录|估计 K、畸变、T_C←W，保留标定图和未参与拟合的验证点。普通录制可跳过并将米制字段置空|移动相机、裁切、分辨率、焦距或防抖策略改变后验证或重标|
|B 静置与拿起|录制开始后手机在标好方向的支架上静置两秒，再拿起自然握稳一秒以上|记录重力方向、静止噪声、时间戳连续性和设备参考系；保留拾取完整区间，估计噪声用于动作门槛|强抖、断流、传感器重启、参考系改变|
|C 握法与朝向|选择左/右手、手机顶部朝向、屏幕朝掌内/外、保护壳及正反手姿势；按图让手机长轴对准场地前向，依提示绕长轴轻转再回正|记录标称 H←D 安装偏置，核对三轴正负。重力确定俯仰与横滚；持机口令只给航向先验，带刚性视觉标记才可独立观测。如果真实动作会换握，记录换握事件并分段|换手、换壳、松握滑动或视觉方向持续偏离|
|D 指定点位|按个人舒适活动范围布置 P0 胸前、P1 持拍侧前方、P2 前上方，三个不共线；使用固定支架或实体标记量出 W 坐标。依次 P0→P1→P2→P0，每点停约一秒|无标记模式只记录“提示到点、用户确认、静止窗口”；有手机壳标记时，以已知边长和相机内参估计 T_C←D，转换到 W 后比较目标位置、朝向和重复回到 P0 的偏差。点位必须测量到同一机身基准点，不以肩高文字替代坐标|标记被遮、角点不足、图像重投影误差大时留在当前点；可退回相对方向模式|
|E 动态验收|从准备位做一次上挑、平抽和下挥，再回到 P0；操作员核对画面与三轴变化|显示手机模型和画面叠加，核对镜像、轴向、重力方向、同步及收拍回正；留一处额外点位仅做验证|画面与模型反向时检查坐标变换；不能用放宽所有识别阈值掩盖|

手机壳标记需刚性固定、测量标记到机身的偏移；手掌或衣服上的标记不能当作手机中心。PnP 存在近平面歧义和噪声，需结合可见边长、正深度、重投影误差和时间连续性筛选。位置不可见时输出缺测及持续时长，可短时预测供显示，训练标签保留缺失掩码。单相机对着地面板建立场地后，仍不能把任意手腕像素通过地面单应直接转换为三维位置。[OpenCV ChArUco](https://docs.opencv.org/4.12.0/df/d4a/tutorial_charuco_detection.html)

## 6. 指定目录的数据契约

Mac 所选目录是权威归档。采用稳定 ID 作关联键，动作中文名只作显示。场次可持续录像并容纳多个试次，避免每拍重复复制视频。按设备源时间、时钟段和帧 PTS 无损回查；摘要可重新生成。

```text
所选目录/

    manifest.json                 # 设备、软件、同意状态、格式版本、关闭状态
    imu/<stream_id>/samples.csv   # 开始即追加；恢复补传可先写独立分片再去重合并
    clocks.jsonl                  # 每轮探测、拟合与独立物理对齐结果
    camera/<camera_id>/part-001.mov
    camera/<camera_id>/frames.csv

    trials.jsonl                  # 试次窗口、任务、分支和重录关系
    events.jsonl                  # 所有操作、状态、报警、提示和预测
    labels/revisions.jsonl        # 人工标注，不覆盖源数据
    derived/<pipeline_version>/   # 关键点、可视化、对齐序列与质量报告
    checksums.json                # 封装完成后记录文件大小和校验值
```

### 交给训练程序的数据包

开发者可以采两类数据：跟随指令完成的单拍，以及实际比赛中的连续回合。采连续回合时保持正常游戏节奏，Mac 连续录制；一段视频可以对应多拍、挥空、回摆和无动作区间。iPhone 同时写出游戏构建号、已有识别器版本及其输出时刻。录完再看视频补标漏拍和错拍，避免只保留算法已经识别出的动作。

每次导出生成一份版本固定的试次索引（建议文件名 trials_index.csv），每行对应一拍或一个明确的背景区间。索引至少含 participant_id、session_id、trial_id、采集模式、IMU 相对路径和序号范围、视频相对路径与 PTS 区间、同步映射版本、提示类别、人工实际类别、标签版本、质量状态和排除原因。跨视频分段的试次附有序片段清单。训练人员按人工复核标签选样；尚未复核的真实回合保留为待标注素材。

**交接验收。** 把导出目录复制到另一台电脑，断开手机并关闭 Mac 客户端。用独立脚本读取索引、检查文件校验值，任选一次正常回球、一次漏识别和一段背景，还原各自的传感器窗口与对应视频片段。三类样本都能定位，且重新导出时可追溯同一份原始记录，即完成采集端交付。

## 7. 视频复核与可选的离线图像处理

1. 实际取景检查。预览叠加头顶、脚边和持机手活动边界；试做最高点与最大侧向跨度。快门拖影、过曝、背光、衣服与背景同色、多个人入镜会破坏标注。先改善光照和角度，再决定升帧率；相机记录真正能持续输出的格式。
2. 原片落盘优先。后续离线视觉工具可对导出视频做人物检测与跟踪，锁定参与者，保留框与关联置信度；遮挡后重新确认身份。可用 Apple Vision 或 MediaPipe 作起点，先保留肩、肘、腕、髋、膝、踝的二维像素和模型原始置信度，再派生夹角、速度和缺测。网络输入裁剪、缩放、旋转、镜像的逆变换须能还原到原片像素。[Apple Vision 人体姿态](https://developer.apple.com/documentation/vision/detecting-human-body-poses-in-3d-with-vision) · [MediaPipe Pose Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker)
3. 将原始二维测量、带先验的单目三维估计、经标定的多视角三角测量或光学动捕分层存储。模型输出即使以米表示，也要核对原点、尺度和深度误差，禁止直接当成场地真值。隐藏手、模糊帧和多人身份冲突标无效；短空洞可画虚线插值，离线导出同时保留掩码。每条试次记录触球附近持拍侧关节可见率。
4. 标记辅助实验优先建立**可独立检验的手机轨迹**；球拍头不等于手机顶部。若要验证真实击球，独立开“持拍击球参考”数据集，球拍、传感器安装、标记位置与持手机实验分域；可用高速视频或音频事件辅助，但需实测音画偏移。普通游戏用户不用举着裸手机全力挥臂还原球拍速度。
5. 数据标注在同步回放中执行：确定动作窗口，分别标注准备、引拍、向前加速、触球代理、随挥与回正；触球不可见时用最早/最晚可能帧围成区间。采集头顶高远、吊球、扣杀时重点保存相似引拍样本。抽取至少 20% 试次双人盲标，报告类别一致率、事件差异及争议清单；复核者可回到未叠加模型的原片。训练可使用银标；正式精度报告单列人工可见、标记和独立参考三种证据。

## 9. 采集计划、实验设计与放行指标

**第一天冒烟。** 两名操作员互换，左右手分别做静置、拿起、点位停留、低手上挑、扣杀和自然回摆。先验证从选择文件夹到重开回放，再查同步偏差和机位遮挡。每次改时钟、持机约定或采集协议后重复。

**首轮数据。** 建议 12 名不同熟练度参与者，每人两次重新握持的独立场次，每次八个专业动作各 8 拍，合计 1,536 个专项试次；另外单列游戏短挥、拿起/放下、调整握姿、走动、换手、误触和无动作背景，每场至少 2 分钟。每场再留一组无提示连续混合挥拍，统计回摆重复、抢拍、慢起手和多人遮挡。按自然左右手招募，不让右手玩家强行模拟所有左手样本。记录自然/轻挥、设备尺寸、手机壳、光照、机位、技术水平。随机化动作块顺序，先预演后正式录，统计重录与排除比例。

**切分。** 先按参与者分训练/验证/冻结测试，再生成窗口或增强；同人同拍的慢放、左右镜像、不同机位不得跨集合。另设留出机型、换握和连续比赛测试。少量样本先报告每类样本数与区间，量不足的动作继续采集。每次训练产出数据清单与哈希、标签与校准版本、模型/配置、随机种子、失败案例和同一测试集的基线对照。

|验收层|建议首轮门槛或报告方式|失败后的产品行为|
|---|---|---|
|文件可靠性|30 分钟连续采集；断网 30 秒后恢复；强退、磁盘不足、相机拔出、手机锁屏各做一次。所有缺口或残片可定位，已封装片段可回放，重复补传无重复样本|显式 partial，保留健康通道和可恢复数据，提示补传/重录|
|运动与视频|支持机型上 100 Hz 请求、正常局域网实得采样率目标 ≥90 Hz；按实际设备节奏计算缺口，单个大于 100 ms 的间隙单列。视频吞吐按协商格式报告，正常运行实际掉帧目标 <1%|禁止写死均匀时间轴，画面提示降格式或暂停训练导出|
|对时与显示|60 fps 且物理对齐事件清晰时，首尾独立事件残差 p95 目标 ≤2 个实际视频帧；正常局域网源样本到 Mac 可视化 p95 目标 ≤120 ms|同步不达标仅入粗类别集；不用于触球时刻或空间轨迹评估|

|游戏识别|独立玩家报告宏 F1、逐类召回、混淆矩阵、未知拒识、每分钟背景误触和每百拍重复触发数。三基础类首轮候选目标宏 F1 ≥0.85、背景误触 ≤1 次/分钟；同时与现版模板比较|发生高频混淆时合并为基础指令或保留研究标签，推迟该细分类上线|
|击球时刻|以人工可见事件区间计算最近边界误差，另报落在区间内的比例、预测晚到的 p95 以及完整动作漏检率；空挥和真击球分别报告|不得以只保留已命中样本的平均误差代表实战表现|

## 11. 开发拆分、交付物与验收顺序

|里程碑|建议工程边界|结束条件|
|---|---|---|
|M1 可录可回放|同一 Xcode 工程新增 macOS 工作台 target；共享模块负责消息、时钟与数据契约；iPhone 采集桥接现有 MotionInput；Mac 独立实现目录、相机与会话写入|真机与 Mac 完成一条从静置拾取到收拍的双流记录；换目录、重开、补传通过；现有单机 CSV 与游戏操作回归通过|
|M2 采集客户端交付|Mac 同步时间线、握姿与校准记录、人工标签、质量报告、可移植数据包；支持读回历史 CSV|两名操作员独立复核同一批试次；导出能复现原帧、原样本与标签；遮挡、无参考和时钟异常有清楚标记|
|后续算法项目：评价游戏收益|离线训练/评估工具，端侧模型适配器，比赛回放跑同一批输入；基线与候选模型可切换|冻结测试集给出混淆、误触、时延与动画误差；负收益可回退；记录模型版本和游戏构建号|
|可选研究项目：空间与全身估计|多视角或参考动捕小集、设备标记、人体模型、端侧推理性能评估|给出单手机能稳定恢复哪些自由度、何时必须拒识或改用模板；有实测证据后决定是否推进全身实时实验|

**优先验证的三个假设。** 第一，采集闭环能稳定保存整段动作，并能找到同一时刻的 IMU 和相机帧。第二，重新握持后仍能区分基础动作和真实背景。第三，在冻结的持拍侧参考数据上，时序估计能带来可测改善。只有第三项成立，再投入复杂全身模型与高成本参考数据采集。
