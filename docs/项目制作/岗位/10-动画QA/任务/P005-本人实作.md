## 两支回放怎样比较

同一背面相机、球路、输入、光照与播放顺序，在两个动作版本上各录两支。每支四球，对应两只手和两个击球时刻。QA 重新排列顺序并另存答案，承诺 SHA-256 为 681d8b607476cbeaefdd30879a6faf0e05abb8f059d6ad89f2cc6067514bcb2d。机位、画面与过场均不显示顺序线索、结果、手别或时间差。每条视频中的四种条件各出现一次，修前／后和截断／完整均对应同一组球。

- **截断片**给首次观察者。按键前的预热照常运行，显示前 59 步和第 60 步的按键姿势，随后切同样的黑场。两种时刻的可见时长都是 1.00 秒。按键帧保留来球球裙方向，避免羽毛因出球方向改变而泄露答案。无后续飞行、球影移动、拖尾或落点。请根据头肩、肘、腕、拍床和球托说明判断；看不清可直接写明。
- **完整片**待首次观察封存之后看。相同的初始条件和 60 步前段，按键后再播 45 步，观察手臂如何减速、拍柄是否连贯、脚如何承重以及何时回位。若只能根据球往哪飞分辨结果，按这个理由如实归档。
- **取证边界**：屏幕上某帧轮廓重叠不能单独证明三维相交。模拟器游戏时钟以 60 Hz 推进，视频中实际编码了多少帧、接触附近有没有跳帧，分别检查原片 PTS 与设备时序。主线程操作模拟器，本岗编译并复算独立 Mac 三帧夹具。[Debug 回放](../../../../../code/Clients/iOS/App/ContactFrameReplay.swift) · [UI 检查](../../../../../code/Tests/UI/ContactFrameReplayTests.swift)

## 不依赖 XCTest 的录像交接

模拟器 ID 为 89B4EB3F-3B23-4F9F-AA91-5D3AC77016A8，应用标识为 com.daokaihua.badmintonrally。新旧版本均采用同一回放代码；主线程先安装对应的 Debug 包。以下从仓库根目录执行，替换输出目录和 stage 名称。录制期间显示原始游戏屏幕，初始系统桌面和结束提示可在放映前裁去。

```sh
device=89B4EB3F-3B23-4F9F-AA91-5D3AC77016A8
bundle=com.daokaihua.badmintonrally
stage=before
for mode in Masked Recovery; do
  xcrun simctl terminate "$device" "$bundle" 2>/dev/null || true
  xcrun simctl io "$device" recordVideo --codec=h264 "/tmp/P005-$stage-$mode.mp4" &
  recorder=$!
  sleep 1
  xcrun simctl launch "$device" "$bundle" -contactFrameReplay -contactBlind "-contact$mode"
  sleep 18
  kill -INT "$recorder"
  wait "$recorder"
  container=$(xcrun simctl get_app_container "$device" "$bundle" data)
  case "$mode" in Masked) timing=masked ;; Recovery) timing=recovery ;; esac
  cp "$container/Documents/P005-$timing-timing.json" "/tmp/P005-$stage-$timing-timing.json"
done
```

每个时序文件应有四个不同片号。截断／完整分别是每段 60／105 步，按键步均为 60，按键后步数分别为 0／45。复跑时先清理旧时序文件或核对本轮写入时间，等待中性片尾出现后取出。若关键帧被跳过或视频中未完整显示，注明片号并复录，禁止拿上一轮完整片替代。
