# 玩法设计师

玩法设计师把玩家要读懂的来球、可以选择的回法和每种结果的复现条件写成可执行的逐球用例。当前交付为 [M1 固定低球基线](任务/M1-基线核查.md)。

| 协作环节 | 工作与交接 |
|---|---|
| 接收方向 | 从制作负责人接收本轮体验目标、生产入口、已知问题及用户的实机反馈，明确要在第几球看到什么。 |
| 设计对照 | 固定来球轨迹、持拍手、来球侧及回法意图，逐次改变起始站位或按键时刻。分别写出可见动作、球路及可接受的挥空结果。 |
| 交给玩法程序 | 提供可复现设置、输入顺序和预期判定。玩法程序负责实现物理、可达性、按键事件和日志。 |
| 交给动画及 QA | 给动画负责人说明近身、远半步、不可达时的玩家意图和比赛机位可见差异。QA 复现原球次，回传逐球日志与录像；玩法设计师核对结果是否与意图相符。 |
| 提交验收 | 列出已核实的证据、争议球次与未验证项。制作负责人决定取舍并提交独立验收，体验放行由独立验收主任签发。 |

每球交接保留构建、场景与资产版本、固定参数、角色起点、按键相对来球的时刻、实际判定、落点和重放位置。源码、样片和实机记录各自注明来源。

本岗持续维护[项目理解、招聘依据与工作计划](项目理解与岗位能力.md)，每项执行记录存入[任务目录](任务/)。
