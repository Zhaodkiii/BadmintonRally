# P002 · 同一低球，提示与实际能否碰球

2026-11-25，玩法设计师。我用固定低球研究玩家看到“能接”后按键，画面和结果能否彼此解释。本人读到两套不同的判定路径，给近、远、超距三球增加了一个可复现的边界用例。

## 我查到的具体差异

[比赛提示](../../../../../code/Clients/iOS/Game/Rally.swift#L403)在普通模式要求横向归一化距离小于 0.52，还检查击球窗口与挥拍范围。[实体键](../../../../../code/Clients/iOS/Game/Rally.swift#L608)检查球是否落地、过网、过高，以及平面距离是否超过 2.40 米，随后绕过普通挥拍范围检查。当横向相差 0.60、纵向相同，按代码比例计算得 1.83 米。此时普通提示必关，按键路径的距离检查却允许继续。这个数值反例揭示两条路径可能分歧。屏幕上是否真的在该位置回球，仍取决于实际角色跑位、其他条件和按键所取历史帧。

## 我交给玩法程序与 QA 的固定输入规格

取同一颗正手侧网前低点下落球的世界轨迹，选择球已过网、尚未落地、在普通窗口且角色可触的同一低点时刻 T。重放同一段轻托动作样本，锁正手、目标直线、输入时间、相机与模拟步长。只拨动角色起点；自动跑位照常推进。先跑无输入基线，再用 T 时刻实际距离校正起点，记录起点和触球帧实际坐标。缺少指定起点的重放入口时退回工程补夹具，UI 远位开关只提供两档。

| 球次 | T 时刻位置要求 | 如何判读 |
|---|---|---|
| A 站稳 | 同纵深，球位于身前持拍侧的短挡范围 | 角色稳定短送，球接触拍面后变向。记录提示与判定。 |
| B 远半步 | 同纵深，球处于短挡之外、单步跨伸可达 | 有支撑脚和伸拍。视频拍面够到才允许回球。用三维拍床证明接触。 |
| C 超距 | 超过同版本 B 实际所示触达极限，并保持在场内 | 按键仍有挥空反馈，来球继续原轨迹；不直接将 2.40 米当作人物臂展。 |
| D 判定分歧探针 | T 时刻横差 0.60，纵差 0，角色位于有效场内 | 预期现行提示关、距离门通过。逐帧检查实际拍床及有无出球；出现隔空回球即登记缺陷。 |

每次导出同一个 flight ID 或轨迹散列、球次、相对 T、按键记录、提示开关、角色坐标、球心、拍床最近点、判定和出球首帧。若三个起点因自动移动收敛成同一触球位置，记为无效对照并调整起点；若 D 的其余条件未满足，重选 T。早按/晚按只在固定 B 的独立时序组测。三站距供 QA 复现，独立玩法验收员以具备原始录像与几何记录的正式比赛为准。
