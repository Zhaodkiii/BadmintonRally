## 工单与版本

负责人派工时给出唯一编号、负责人、协作岗位、预期交付、依赖、可编辑范围和验收人。跨岗位同一工单在各自“任务”目录留一份本岗记录，相互引用。后续工单用“里程碑-序号-主题.md”。沿用已有工单时按日期追加进展，保留失败与返工结论。

状态依次为待办、进行中、待验收、已验收；发生失败或依赖缺失时写返修中或阻塞，并记下解锁条件。已交付岗位记录与产品通过测试分别判定。未跑真机或只做只读检查时，必须明确所能证明的范围。检查人给出依据，制作负责人登记组内验收结果。正式体验由独立验收主任签发放行或退回，制作方负责执行。

每张任务单记录日期、任务号和状态；随后写明目标和通过条件、已做工作、复现步骤或命令、产物路径与版本、预期和实际、已达到和未达到、下一位负责人及检查人。视频记录球次和时间码；测试记录退出状态和失败位置。Git 工作树已有改动时保留现场，必要时用资产哈希标识实际测试版本。

后续任务从[工单模板](工单模板.md)复制到主责岗位的“任务”目录；协作岗位在自己的任务单引用同一编号。
