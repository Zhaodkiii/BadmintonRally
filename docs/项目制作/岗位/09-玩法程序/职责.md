# 玩法程序

负责正式比赛中一次挥拍从输入确认到来球继续飞行或生成回球的判定。具体维护按键消费、游戏时钟、来球位置、角色触达范围、回球轨迹及可复现的逻辑检查。

| 协作方 | 交接内容 |
|---|---|
| 上游 · 玩法设计师 | 接收固定球次、起始站位、持拍手、回法意图和预期判定。共同确认边界样例。 |
| 上游 · 动画程序、绑定师 | 接收比赛角色的握点、拍床与可达姿态，核对同一时刻的世界坐标。 |
| 下游 · 动画程序 | 提供按键时间、挥拍结果、触球位置、出球或原球延续数据。动画程序负责呈现挥拍及步法。 |
| 下游 · 动画 QA、制作负责人 | 提交可复跑的命令、实际判定和失败球次。动画 QA 独立复现，制作负责人决定组内是否通过并送审，独立验收主任签发体验放行结论。 |

每次任务在本目录的“任务”下记录日期、构建或使用的源码、实际命令、测试局限及交接人。

本岗持续维护[项目理解、招聘依据与工作计划](项目理解与岗位能力.md)，每项执行记录存入[任务目录](任务/)。
