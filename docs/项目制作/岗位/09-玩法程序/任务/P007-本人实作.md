# P007 · 后场到位与底角绕头

2026-11-25，09 玩法程序。用户反馈后场跑位错误。我在 Mac 离线复现并改动正式 Rally.approachIncoming，随后重跑原球。输入、落点、脚速上限、得分规则和球拍拍床判定均沿用同一版本。没有操作模拟器或实体手机。

## 两个可复现的问题

1. 对进入后场的高球和平快球，原先直接把脚中心横坐标设为拦截点横坐标。右手正手和左手正手都跑到球正下方。反手底角从场地另一侧远起步时，60 Hz 样本甚至跑过了球线，预测拦截点落在人物持拍侧 6.85 厘米。
2. 原先为所有区域先多退 26.8 厘米，再在击球前 140 毫秒更改目标。普通正手高球触球帧的脚位中心仍以 1.68 米/秒前移，反手底角近位为 1.80 米/秒。

我把后场站位作为预测候选的一部分。正手或追身球为持拍肩留出 24 厘米横向空间。非持拍侧高球按高度与剩余移动时间判断，能提前到位时给绕头动作留 12 厘米；时间不足则留 34 厘米反手接球空间。每球只向最终后场站位减速一次，保留前中场深度微调。候选使用现有按方向跑速与加速度预算，不读训练中的目标回法。[源码](../../../../../code/Clients/iOS/Game/Rally.swift) · [本次差异](P007-证据/后场跑位.patch)

## 实测

左右手 × 近远起步 × 30/60/120 Hz；每种组合覆盖高球和平快压底线的正手侧、反手侧、追身，以及反手底角，共 84 个球次。对齐球次后，修前修后的来球目标与预测拦截点 84/84 相同。以下为右手、60 Hz，偏移量从脚中心量到预测拦截点，正值为持拍侧，速度为游戏内脚位中心逐帧平移速度。

| 输入 | 横向偏移，修前 → 修后 | 触球时脚位速度，修前 → 修后 |
|---|---:|---:|
| 正手高球、近起步 | 0 → +24.0 cm | 1.68 → 0 m/s |
| 反手底角、近起步 | 0 → −12.0 cm | 1.80 → 0 m/s |
| 同一反手底角来球、远起步 | +6.85 → −34.10 cm | 2.04 → 0 m/s |
| 反手侧平快球、远起步 | −60.97 → −69.68 cm | 4.18 → 3.22 m/s |

修后 84 组均获正式拍床接受。全部 48 个高球与反手底角球次的触球帧脚位中心已停止。近起步反手底角左右手均识别为可绕头，远起步两手均保留反手站位。平快球从远位横穿球场时仍有移动中接球的样本。修前也有 84 次成功回球，改进集中在击球位置与减速时机。[修前逐球](P007-证据/修前.csv) · [修后逐球](P007-证据/修后.csv)

正常按键 ButtonContactChecks 和计分 RulesChecks 均退出 0。用 P006 的标准 AI、种子与虚拟玩家复跑正式单打，比分由 0∶0 至 21∶5，26 分、50 次成功回球，游戏时间 163.367 秒。[正式比赛流水](P007-证据/修后正式单打.tsv)

## 复查方法与边界

在项目根目录执行。程序断言高球的触球侧与停步、近起步可绕头、远起步反手空间及全部有效接触。加入 --observe 可对旧源码输出同字段，跳过新站位断言。Rally 源码 SHA-256 前十二位修前为 cf17db61d611，修后为 0cf0c5bfa77d。

```sh
p='docs/项目制作/岗位/09-玩法程序/任务/P007-证据'
t=$(mktemp -d)
swiftc -O code/Clients/iOS/Game/Rally.swift code/Clients/iOS/Art/{ReturnMotion,SpatialCourt}.swift "$p/后场跑位复测.swift" -o "$t/check"
"$t/check" > "$t/current.csv"
diff "$p/修后.csv" "$t/current.csv"
```

交独立验收复查左右底角、头顶与远起步的比赛机位，并将用户原球次与测试几何对齐。现有数据能确认游戏脚位与有效触球；真实人体动作、骨骼脚底是否滑动以及用户反馈的原球是否属于同一故障，仍需对应证据。
