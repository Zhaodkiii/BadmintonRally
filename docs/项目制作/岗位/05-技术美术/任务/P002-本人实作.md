# P002 · 从 R34 短挡成片追到比赛球员节点

2026-11-25，技术美术本人执行，已交动画程序，待制作负责人及独立主任检查。

我选近身短挡作为能由同一台 Mac 复查的例子。先算美术成片与工程副本的 SHA-256，再写探针重开工程 SCN，同时用比赛的 CourtScene 源码实例化另一份场景，分别取 V2Player 下的 StringBed。两个构造过程都在本次探针中执行。[探针源码](P002节点实查.swift) · [正式比赛与预览入口](../../../../../code/Clients/iOS/UI/ClubView.swift)

半轴由圆环中心线半径乘以拍床对应轴的局部缩放得到，仅反映拍框尺寸。玩法命中还需独立定义有效拍床及球托半径。比对的是初始化节点；这组数值无法推断人物站立身高。比赛以 pose 逐帧更新程序化角色，因此初始化时零个动画键仍能在运行时产生动作。

**发现。** 两端复用了 V2Player、StringBed 命名和拍框尺寸，当前正式入口经 SpatialCourt 创建 CourtPlayer，再由 styleHeroine 命名和装配。预览才按动作选择 SCN。相同节点名和尺寸不足以追溯成片版本，比赛近端球员仍需接入 R34 来源。场地坐标由 world 映射到米，场宽坐标乘 3.05，纵深为 (y − 0.5) × 13.4，高度按网高换算。接入时须先把角色局部拍床变换到同一世界空间，再与球托对齐。[比赛角色构造、坐标变换及每帧姿势](../../../../../code/Clients/iOS/Art/SpatialCourt.swift) · [预览加载](../../../../../code/Clients/iOS/UI/PlayerPreview.swift)

## 复查

在仓库根目录执行以下命令。编译和探针本次退出状态均为 0。两份短挡文件的摘要均为 e18acc216ba2922ab9120174ec2b8b3e520c887dccb54e6bd36b48a54d0ab162，比赛渲染源码摘要为 80ed63f4b71b71d242e5e33b21b5e16707ea9daf91fab7855e02643816b3cb12。

```sh
shasum -a 256 assets/美术/女球员独立制作/R34动作样片/近身短挡/成片.scn code/Clients/iOS/Resources/RallyPlayer.scnassets/block.scn code/Clients/iOS/Art/SpatialCourt.swift
t=$(mktemp -d)
swiftc code/Clients/iOS/Game/Rally.swift code/Clients/iOS/Art/ReturnMotion.swift code/Clients/iOS/Art/SpatialCourt.swift docs/项目制作/岗位/05-技术美术/任务/P002节点实查.swift -o "$t/probe"
"$t/probe" code/Clients/iOS/Resources/RallyPlayer.scnassets/block.scn
```
