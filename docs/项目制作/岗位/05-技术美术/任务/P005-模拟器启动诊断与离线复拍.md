## 启动服务停在哪里

设备列表显示 Booted，宿主上 launchd_sim、SpringBoard 与 backboardd 都存在。启动链中的 bootstatus 已挂起约 15 分钟，另一路 get_app_container 已等约 14 分钟，安装旧版的 install 也在排队。单独限时查询同一 UDID 的 app 路径，在 4 秒内没有返回。数据卷约有 24 GiB 可用。系统日志未提供导致阻塞的明确错误。

在同一设备进程树中，连续 1 秒采样迁移服务，887 次执行样本均显示其在读取上次构建偏好 lastBuildVersionPref 时等待用户偏好服务的同步 XPC 回复。同期另取 1 秒，模拟器 cfprefsd 的两条工作线程在偏好请求或连接激活期间，均阻塞于活动日志流发送。该样本定位了当时的等待链，更底层的日志服务为何未排空仍未知。启动等待端没有返回具体的迁移插件名。

**接回同一设备的操作顺序。** 由当前录制负责人保留一个启动监视窗口，先清点已排队命令及其父 shell，特别是等待成功会自动继续 launch 的两条链。有重复启动意图时，由该链的所有者取消自己的整条命令；单独中断子查询后，用分号串联的 shell 仍可能继续启动。保留唯一录制负责人，等已有 bootstatus 完成后，先执行下列路径查询并确认安装的构建。按修前、修后分别串行安装和录制。若再超时，保留当前运行与样本，离线片照常进入渲染评审；模拟器录像继续待取。本次未接管设备或操作界面。

```sh
ud=89B4EB3F-3B23-4F9F-AA91-5D3AC77016A8
xcrun simctl list devices booted
ps -axo pid,ppid,etime,command | rg 'simctl (bootstatus|get_app_container|install|launch)'
# 已有启动监视结束后，单次限时查询安装位置。
python3 - "$ud" <<'PY'
import subprocess, sys
try:
    p = subprocess.run(["xcrun", "simctl", "get_app_container", sys.argv[1],
                        "com.daokaihua.badmintonrally", "app"], timeout=8)
    raise SystemExit(p.returncode)
except subprocess.TimeoutExpired:
    raise SystemExit("8 秒内无包路径，设备仍待恢复")
PY
```
