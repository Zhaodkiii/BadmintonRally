# P005 · 正式比赛反手平抽和挥空动作

2026-11-25 · 07 动画师本人制作 · 状态 待验收 · 接收人 02 动画负责人、10 动画 QA

我以 P004 的正式比赛角色为底版制作了三处姿势与曲线，08 动画程序按约定合入其独占编辑的 SpatialCourt.swift。游戏的 CourtScene.update 经 poseNear 调用同一套动作；左右手用持拍侧符号镜像。[正式比赛动作源](../../../../../code/Clients/iOS/Art/SpatialCourt.swift) · [本岗制作的实际补丁](P005-证据/07动作改动.patch)

- **准备**：平球接近时让非持拍肘向外略向后打开，由左右手方向和支撑相位驱动。先固定上臂方向的长度再加偏转。第一稿同时推上下臂，平衡手最大可多偏约 37 厘米，我撤掉了该做法。最终 F78 的非持拍手比旧版偏 6.0 厘米，拍床位置保持一致。
- **回击**：已判定反手平抽时，触球后 20 毫秒才开始增加朝出球方向和持拍侧的短送，115 毫秒处制动，再用 200 毫秒消去附加位移。右手 −50 毫秒样本在 F87 接回，F91 拍心相对同帧旧版多向持拍侧 2.7 厘米、向上 1.2 厘米、向前 2.7 厘米，F109 回到原有轨迹。
- **挥空**：保留按键当帧及随后一帧的救球原姿态，随后让空挥拍头绕回持拍侧并略下沉，165 毫秒才开始折返，410 毫秒回到守备目标。右手 −100 毫秒样本在 F84 按键，F88 拍心比旧版多向持拍侧 21.5 厘米、低 5.1 厘米；F92 分别为 45.7 和 10.8 厘米。固定镜头能见球从拍头下方经过。第一版沿原来的横扫方向再拉远，框在头肩后更难读，已据渲染退回并重做。[同机位姿势对照](P005-证据/背面同机位对照.jpg)

## 我怎样复核

取现有几何夹具相同的中场站位、60 Hz 来球、挥向与力度。左右手各打 −100 与 −50 毫秒两球，采用生产 Rally.swing 的拍床验证回调，逐帧采样实际 StringBed 与 BalanceHand 的世界位置。CSV 有四球各 65 行，单位为米。取 P004 底版（SpatialCourt SHA-256 前缀 83a1a2c65be1）与只施加本岗补丁的版本（dc7a273e15f4）做因果对照，避免混入 08 同轮手腕改动。联系表在 874 × 402 的 Mac SceneKit 离屏画面上固定裁切，像素原大、未逐帧重构图。[完整数值](P005-证据/动作逐帧对照.csv) · [拍摄源码](P005-证据/复拍.swift) · [几何取样源码](P005-证据/轨迹复测.swift)

右手 −100 毫秒 F84～F92 的球托至有效拍床净距依次约为 72、37、100、111、177、315、484、671、866 毫米，球继续原来球路。独立画面中的按键当帧仍可投影重叠。本岗提交的是动作实现和几何对照，正常大小、静音、不带拖尾的新观察者能否在后续球路揭示前认出失手，留给独立视觉验收。

在仓库根目录用 Mac 复拍，输出目录须先建立。取不同版本时替换 SpatialCourt.swift 的路径，保留其余输入和相同摄像机。几何取样使用同一编译命令，将末尾的复拍.swift 换成轨迹复测.swift，直接运行二进制即输出逐帧 CSV。

```sh
evidence=docs/项目制作/岗位/07-动画师/任务/P005-证据
run_dir=$(mktemp -d)
xcrun swiftc code/Clients/iOS/Game/Rally.swift code/Clients/iOS/Art/ReturnMotion.swift code/Clients/iOS/Art/SpatialCourt.swift "$evidence/复拍.swift" -o "$run_dir/render"
"$run_dir/render" "$run_dir" > "$run_dir/轨迹.csv"
```

最终独立动作版另跑 ThreeFrameContact，八例断言退出 0。24 行三帧结果与 P004 封存 CSV 逐字节相同（SHA-256 前缀 e2361ec65473）。[对照基准](../../10-动画QA/任务/P004-证据/终候选三帧.csv)
