# 晚风球社工程项目总纲

**当前 iOS 运行与测试目标**　仅使用 iPhone 18 Pro 模拟器（iOS 27.2），禁止使用个人实体手机。运行参数与硬件项记录方式见[项目设备约定](运行与测试设备.md)。

制作负责人为本项目主线程。用户确定产品方向，负责真机体验反馈；制作负责人承担日常派工、跨岗位取舍、构建、问题追踪、内部验收与返修。基线日期为 2026-11-25。

## 最终总目标

交付一款在 iPhone 上可独立完成整场单打、可投屏到电视的 3D 体感羽毛球游戏。玩家能从第三人称画面读出来球的高度、前后和左右位置，自主选择回法；按音量键确认击球时刻，按键前的挥动方向、角度与力度连续影响球路。角色跑到可拦截的位置，以真实可达的步法伸拍、触球和回位。玩家应能从画面理解为什么这球回深、回浅、下网或挥空。Mac 工作台服务于开发，能够把一次争议判定还原为一球可重放的证据。

最终验收使用下列可观察结果。正式构建、真机录像及原始日志共同用于签字。

| 范围 | 完成证据 |
|---|---|
| 完整比赛 | 从首页进入正式球场，完成发球、接发、连续回合、得分、换发和结算。真机与投屏分别记录击球到反馈的时间。 |
| 自由选打法 | 覆盖网前、中场、后场九种来球场景及对应 27 项回法，另测四种发球。固定同一颗球，改变挥向、力度或接球时机，左右落点、深浅、弧高和速度有可解释的变化。 |
| 角色可信 | 正式球场与预览复用已验收的比赛角色及动画来源。主要打法在比赛尺寸下可辨，包含步法、触球和恢复。关键帧核对拍面、握点、脚底、关节和衣发；出现穿插可定位到资产、姿势或过渡帧。 |
| 输入可信 | 一次按下最多对应一次尝试，无按键的晃动不会产生回球；可达性与球网、界线决定结果。按键、拍面和球变向的时间差可复盘。 |
| 可持续改进 | Mac 按场次和球次关联来球、玩家意图、按键、IMU、实际回球、拒绝原因及录像。每次识别或动画更新重跑相同失败球，保留构建与资产版本。 |

## 团队与决策权

项目有一位[制作负责人](../../.codex/agents/producer.toml)和十个专业岗位。岗位配置在仓库中持久保存，执行时按工单启动。每个工作包有一个主责人；共享代码由主责人合入，制作人处理意见冲突。

| 岗位 | 对哪项结果负责 | 交付给谁 |
|---|---|---|
| [玩法设计师](../../.codex/agents/gameplay_designer.toml) | 固定来球、可选回法、命中与挥空的复现条件 | 玩法程序、QA |
| [动画负责人](../../.codex/agents/animation_director.toml) | 比赛机位的轮廓、动势、击球侧与支撑脚标准 | 动画师、制作负责人 |
| [角色美术](../../.codex/agents/character_artist.toml) | V2 角色的造型、服装、发型和背面剪影 | 绑定师、技术美术 |
| [绑定师](../../.codex/agents/rigger.toml) | 骨架、蒙皮、关节活动范围、握柄与极限姿势 | 动画师 |
| [技术美术](../../.codex/agents/technical_artist.toml) | 导入、版本、坐标、材质和真机性能基线 | 动画程序 |
| [体育动作顾问](../../.codex/agents/sports_advisor.toml) | 真人参考时间码、脚步与发力阶段、标注不确定性 | 动画负责人 |
| [动画师](../../.codex/agents/animator.toml) | 可播放的准备、触球、随挥与恢复，帧上接触标记 | 动画负责人、动画程序 |
| [动画程序](../../.codex/agents/animation_programmer.toml) | 比赛角色加载、移动与动作过渡、脚锁定和拍面对齐 | QA |
| [玩法程序](../../.codex/agents/gameplay_programmer.toml) | 击球时间、触达、物理、得分和逐球日志 | 动画程序、QA |
| [动画 QA](../../.codex/agents/animation_qa.toml) | 独立重放、真假穿模判断、返修回归和真机证据 | 制作负责人 |

## 首轮工单 M1：同一颗低球的三种结果

**状态：已启动基线核查，正式球场的角色接入与真机验收待完成。** [独立样片终验](../../assets/美术/女球员独立制作/R34动作样片/制作与终验.md)记录了近身与远身在 151 个采样点有相同球路，两段均在 0.575 秒触到同一处拍床。这个时间是样片内的时间，实战以当次按键和游戏时钟为准。当前[正式比赛入口](../../code/Clients/iOS/UI/ClubView.swift)走 [SpatialCourt](../../code/Clients/iOS/Art/SpatialCourt.swift)，[角色预览](../../code/Clients/iOS/UI/PlayerPreview.swift)加载 R34 的独立场景。

| 顺序 | 主责与依赖 | 交付和判定 |
|---|---|---|
| M1.1 固定失败球 | 玩法设计师，QA 复现 | 以相同来球、持拍手、回法意图固定 A 近身、B 远半步、C 够不到。记录起始站位、球轨迹或种子、按键时刻及场景版本。先核对三条来球轨迹一致。 |
| M1.2 统一角色 | 技术美术，绑定师与角色美术协作 | 核对预览与包内资产，给比赛提供同一角色来源，标明身高、朝向、握点和拍床。动画负责人在比赛背面及侧面验收站立、屈肘、跨步。 |
| M1.3 接通一拍 | 玩法程序拥有击球事件，动画程序拥有角色呈现 | 同一球次内比较按键时的球、角色触达范围及实际拍床。A 双脚站稳、短挡过网；B 跨步压髋、拍床触球并回球过网后回蹬；C 有收拍、球继续飞。按键只确认击球时刻，提前追球和超出范围有独立结果。 |
| M1.4 复验与放行 | 动画 QA，制作负责人送独立委员会签字 | 固定测试走正式比赛渲染与判定路径；另从首页“开始比赛”打一回合验证生产入口。逐球看背面、侧面、逐帧日志，重跑无按键、长按、同球重复和暂停恢复。保留实机包版本、录像及已知缺陷。 |

现有可用入口为“场景采集 → 网前 → 固定来球 → 网前低点下落球”，可切换“远位起步”；“中场 → 接杀防守 → 接杀挡网”用于短挡对照。两种不同来球的录像只能作补充。正式的同球 A/B/C 对照固定同一条世界轨迹、持拍手、挥拍输入和相对回合时钟的按键时刻，只改变起始站位。早按、晚按和未按另列回归，分别记录挥空原因。

## 每轮如何处理失败

工单由制作负责人记录 **球次、构建、角色版本、来球、目标回法、实际结果、失败帧、责任岗位、修复版本和复验结果**。若时间轴不一致，玩法程序先核对游戏时钟和按键；若拍面在准确时刻够不到球，动画程序核对站位与可达性；若多机位都看到身体穿插，绑定师和动画师核对姿态；若仅背面读不清，动画负责人组织调整轮廓。先用原失败球复测，再重放已通过的另外两球。负责人在证据齐备时提交独立验收，用户反馈作为新的实战回归用例。

## 后续里程碑

M1 放行后，M2 把头顶进攻、反手底角、网前机会球接入同一套角色与回放流程，验起跳换腿、落地和接下一拍的过渡。M3 逐组扩至九种接球场景和四类发球，分别评估左右手、力度梯度、方向和早晚击球。M4 验完整单打、连续比赛帧耗、实际投屏延迟与陌生玩家上手体验。每次扩展保留可复现的旧用例；更换引擎等涉及大范围迁移的取舍单独列明成本与对照证据。
