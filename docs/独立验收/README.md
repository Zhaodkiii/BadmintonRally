# 独立验收委员会

**当前 iOS 运行与测试目标**　仅使用 iPhone 18 Pro 模拟器（iOS 27.2），禁止使用个人实体手机。运行参数与硬件项记录方式见[项目设备约定](../项目制作/运行与测试设备.md)。

适用范围为晚风球社正式比赛的角色动画、来回球玩法、画面可读性及体验版本放行。制作团队负责交付候选版本与返修，验收委员会单独向项目所有者报告。制作组动画 QA 继续负责组内测试。委员会独占对标签字权；制作负责人收到退回必须重新派工。

## 判决与打回

1. 提测单写明构建号或哈希、角色版本、设备与显示模式、正式入口、固定来球和按键脚本、原始录像与对应日志。缺少可核对的正式入口证据，标“退回补证”；目测独立样片只计样片范围。
2. 验收员复跑近身可达、远半步可达、超距三种结果。固定来球、持拍手、输入和按键时刻，再单独测早按、晚按及无按键。继续核对同一高球的吊与杀、上挑和左右线路；逐项标明本轮实测覆盖。
3. 视觉检查先用正常速度、正式机位和正常比赛人物尺寸辨认来球、起拍、触点、回位；再用侧面和球次日志区分遮挡、穿插、时钟错位。提测方需提供成功球和失败球。
4. 实测违反必过条件标“退回重做”，无法判断标“退回补证”。任一必过项失败或缺证，本范围不得标为通过。参考片里的字幕、音效、颜色、Joy-Con 键位与本作不同，按共同的可读反馈和战术选择评判。本作继续用音量键确认击球时刻。
5. 每一项退回列工单号、失败或缺证理由、证据位置、主责岗位、可复现重测条件。下一候选使用新的审查编号，引用原结论，重放原失败球并跑已通过的邻近用例。制作负责人可安排内部测试，体验对标的最终裁决归验收主任。

## 每个正式候选的整局复赛

1. **冻结并实打整局。** 验收员取得候选构建、角色与镜头版本、脚本及其指纹，亲自在指定模拟器从应用首页进入正式单打。开始操作前启动连续屏幕录制，比赛从 0:0 打到胜负确定。让原生结算页停留到比分、回球次数及最长回合清晰入镜，再停止录制。每局独立归档原始视频和同局事件流水。
2. **注明输入来源。** 送审记录分别标明模拟器实际界面操作、程序注入的动作或按键、离线引擎回放。固定脚本记录种子、频率、持拍手、难度、注入位置及主动留空的球次。模拟器不能验证的真实 IMU、实体音量键触发及硬件延迟，列为未验证。Mac 离线全局的几何、时序结论单列；正式界面与观感由该候选实际 iOS 录像验证。
3. **先看整局，再定位到帧。** 先按原速和比赛尺寸观察发接、移动、迎球、触拍、回稳、得失分和结果页。逐分对照一次加分、下一发球方及结算值。围绕成功球、失败球、历史退回球和异常过渡逐帧复查，记录比分/第几分、游戏秒、视频时码、具体帧和输入。检查镜头留边、HUD 遮挡、脚底穿地、关节与衣袖连接、拍面和球。标明游戏步与视频帧各自采样率、时间对应误差及画面遗漏。
4. **签发并打回。** 主任把实测项目、缺证项目、可重放的失败球、原因与证据写入该版本独立判决，明确返修主责及验收条件。录像缺失、片尾无可辨结算或未能关联同局流水时，整场送审退回补证。每种局部样片、离线报告和截断盲读只给其实际覆盖项目记成绩。
5. **返修版本重新打完整局。** 下一正式候选重新冻结指纹，验收员从首页再打一局并重新录屏。以相同输入与比分重放原失败球，也复检此前通过的邻近发接、失误及计分，核对修复是否引入新的动作或显示问题。保存前一轮原判、返修单与新判的相互引用。按可复核的构建和实测范围签字。

P006 的 A 版在 17:4 挑高时出画。B 版回到同一球并完整打至结算，两个构建分别保留了原始录像、球次与判决。[查看整局复赛实例](00-验收主任/任务/P006-整场裁决.md)
