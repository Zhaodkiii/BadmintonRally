# 十四项真人挥拍与模拟训练方案

**训练决策**：先复核真人正负动作，用小特征集的 RBF SVM 做离线对照。待独立玩家和连续回合覆盖充分，再用相同切分评估轻量 CNN。第一项验收是抖腕少误触的同时保住轻放网和短发。

## 本轮实测，2026-11-23

扫描整个动作采集根目录。57 个专项场次中 56 个完整，14 类各 4 场；一个中断场次排除。训练和留出均为 P01。每个专项场次在采集动作窗口内选一个角速度模长最大点，以任务名作弱标签。逐拍人工复核标签为零。另有 9 个实战目录；已从批次汇总 614 个检测候选，其中 337 个可按时钟记录定位到摄像头录像。候选包括拒绝项，连续视频中还需主动寻找漏检拍。

camera.mov 使用 Apple Vision 离线提取持机侧手腕。用 clocks.jsonl 拟合手机到 Mac 时钟，按 frames.csv 定位视频 PTS，在 IMU 主峰前后约 267 ms 逐帧估计二维手腕位置，要求单人、关节置信度至少 0.30，取相邻有效帧的最快位移中点。56 场均有至少 6 段可用速度估计；IMU 候选到最近相机帧的时间取整误差最大 16.6 ms。腕速峰与角速峰的绝对时间差中位数 83.5 ms，仅 31/56 在 100 ms 内。窗口边缘峰要扩大范围复核；运动模糊、遮挡、投影方向和腕部转动都会改变二维腕速。它是独立的动作线索，空挥记录只能给出虚拟击球区间。此分析未逐帧人工确认所有真实挥拍瞬间。

## 从关键点进入训练

逐场 video_peaks.csv 保留峰值样本时间、对应视频秒数、角速、该瞬间的线加速度模长、主峰宽度、腕速时间差和竞争峰比例。20 场存在距主峰至少 250 ms、速度仍超过主峰 80% 的另一段运动。先在这些视频中确认是否为引拍、击球、第二拍或回位。针对放网/挡网，优先标注前伸起止、减速、来球情境；对扣杀/高远/吊球，比较相同准备姿势下主挥方向和随挥。相同侧面的腕速峰只用于定位录像，无法独立监督精确触球。

第一项基线沿用游戏六轴峰前 150 ms 的归一化曲线。第二项实验保留幅度，以 100 Hz 重采样峰前 240 ms 到峰后 80 ms，分六段计算各轴均值，再加峰速和峰加速度；用训练集统计量标准化并拟合各类中心。固定 42 场训练、14 场留出，分别命中 3/14、6/14。后者使用未来 80 ms，端侧需计入确认延迟。录像只在开发阶段辅助时间定位和质量复核；两个基线均只用手机信号做预测。尚无独立新玩家验证，也没有证据支持更换客户端模型。

复现顺序：用 Tools/train_curves.py 的 --allow-prompt 生成新版本目录；用 swiftc 编译 Tools/review_wrist.swift，运行 Tools/audit_stroke_peaks.py，传入原始根目录、版本目录和 Swift 工具路径；再以同一根目录和版本目录运行 Tools/train_stroke_phases.py。每版保留数据切分和混淆结果。

## 持续录入专项与实战

1. 下一轮先让至少 5 名新玩家各做 14 项，每项两档、每档 5 次，分两天录；这个计划可增加 700 个有意图的动作。特别记录主力手、持机方式、机型、遮挡与失败尝试。后续扩至每类数百拍时优先增加玩家与场景。随机打乱相似动作次序，避免只学到固定喂球顺序。
2. 保存不间断 IMU、时钟探针、视频、每帧时间表。每拍标准备/引拍起止、主挥、允许触球区间、随挥结束、实际动作、置信度及可见性；对难例双人独立标注，记录分歧。视觉差时保留“未知”。增加连续两拍、挥后调整、仅引拍、走动和手腕抖动等负例。
3. 每场实战以 match ID、批次和手机时间去重。match_review.csv 的系统候选仅作为复核索引；同时抽看整段无候选区间标漏拍。先分玩家和日期，再切窗口；增广、相邻帧和同一回合放同一集合。无人复核实战用于回放压力测试，有确认的拍才进入监督数据。
4. 首先训练是否主挥及分段边界，再在候选上预测动作族、14 类专项及未知。数据足够后比较小型因果 1D CNN/TCN 与曲线、分段特征基线。游戏情境作为单独输出层：比较仅 IMU 与 IMU 加情境，识别意图与最终出球分别计分。
5. 在封存的真人连续回合上一对一匹配。报告每类召回和宏 F1、每分钟误触、第二拍召回、同拍重复率、人工虚拟触球区间外误差和 P95 判定延迟。单列左右手、新玩家、轻动作。发布须与当前版本同片对照，实机旁路评估后再灰度。

## 首轮补录与人工复核操作单

- **取景**。用实际游戏姿势试做最大扣杀和最小短发，在 Mac 预览里确认持机侧肩、肘、腕、手机能从引拍一直看到回位。记录相机侧别、坐姿或站姿、惯用手；开场用首帧和时钟探针确认摄像头已经覆盖第一拍。
- **每位玩家的正例**。上述 700 拍正例计划分两天完成，两档分别为慢速示范、正常实战。将后场高远/扣杀/吊球、网前放网/挡网、反手短发/偷后场安排为相同握姿和准备姿势的随机交替试次。给出动作意图，赛后独立复核实际完成动作。允许打错、迟疑和中途收手。
- **额外负例与连续流**。建议每人每次另录原地转腕、调整握持、仅引拍后回位、挥后收手，各做 5 次，保留每组前后等待。再录单拍收手与正反手连续两拍交替、至少一分钟自然等球。负例另计；前臂确有短促前送的挡网和网前放网属于正例。记录负例总时长才可计算误触/分钟。
- **标注顺序**。第一遍隐藏旧引擎结果，在整段录像上圈出意图与实际动作，含完全没有系统候选的拍。第二遍看六轴曲线细化引拍、主挥、触球允许区间及随挥边界；对竞争峰分别标引拍/主挥/收手/另一拍。每行索引含玩家、场次、时间、左右手、可见性、动作标签来源、复核人及版本。遮挡严重且两人无法判断的样本保留为未知，放入诊断库。优先处理 20 个竞争峰场次和两对易混动作。[专项关键点](/Users/hua/Downloads/动作采集分析/14项动作基线-20261123/video_peaks.csv) · [实战复核队列](/Users/hua/Downloads/动作采集分析/14项动作基线-20261123/match_review.csv)

## RBF SVM 和 CNN 怎样用于手机实战

**论文数字的适用范围。** 开源项目报告 RBF SVM 97.43%、CNN 97.87%，输入是球拍安装的六轴 IMU，5 人共 9,784 拍。其八类由四种后场动作分别在有球和空挥条件下组成。游戏里一次有意的空挥就是有效输入，把该项目的 fake 类当负例会教给模型错误的目标。作者按中心前后各约 0.5 秒切窗，这一时间代价也不能直接带入电视游戏。README 描述 60/20/20 切分，但公开的两份训练脚本均以样本随机切出 25%，未按玩家分组且没有固定随机种子。仅凭这些脚本无法确认报告数字对应的精确切分，也不能推断陌生玩家表现。[作者结果和方法](https://github.com/PhusNguyen/Realtime-IMU-Badminton-Stroke-Recognition) · [SVM 代码](https://github.com/PhusNguyen/Realtime-IMU-Badminton-Stroke-Recognition/blob/main/ClassicalML/training/SVM_training.py) · [CNN 代码](https://github.com/PhusNguyen/Realtime-IMU-Badminton-Stroke-Recognition/blob/main/DeepLearning/training/DL_training.py)

**实验 A：先用 SVM 学有效挥拍。** 在连续约 100 Hz 信号上以宽松活动触发生成候选，记录触发自身漏掉的拍；从人工选定的背景和转腕片段用同一流程生成负窗。标注阶段可以看全片，推理只读当前及历史采样。离线对照先复用已有峰前 240 ms、峰后 80 ms 的窗口，再测试缩短峰后等待的版本。训练用实时可发现的候选峰，与人工区间匹配；若直接用人工挑选的最大峰，另列为理想切窗实验。

1. 从少量可解释特征开始：握姿参考系下的三轴角速和加速度分段均值、角速度净积分/累计绝对积分、加速到峰时长、峰后衰减、前送与制动的符号顺序。比较“只有幅度”“加入方向”“再加入时序”三个版本。网前正例和转腕负例按玩家、速度范围配对，同时保留自然分布的验收集。用实际样本检验每组特征的增益。
2. 建立两份训练表。表 A 为有效主挥/非击球二分类，表 B 为复核通过的 14 类正拍。未知样本单列。先在摄像头覆盖充分的连续片段上冻结测试玩家，余下玩家用分组交叉验证做选型。只有 P01 时按场次做探索并披露限制；不能从当前 56 个专项正窗估计转腕误触率。
3. 在每个训练折内拟合 StandardScaler，再拟合 RBF SVC。以 C 取 0.1、1、10 和 gamma 取 scale、0.01、0.1 为初始验证网格，与线性 SVM、现有曲线模板同折比较。类别权重按训练折设置。首轮不固定使用 122 特征或 40 维 PCA；后续若增加特征，将 PCA 也放入训练折，并比较有无降维。用独立验证玩家选择二分类放行阈值和多分类分差弃权阈值；SVM 分数需经验证才能解释为置信度。
4. 表 A 放行后才运行表 B。专项证据弱时记录未知或动作族；表 A 证据弱时等待或拒绝。训练时把握姿校准参数作为该玩家开局可获得的输入。将模型、归一化统计、轴方向、单位、采样率、窗口、阈值与切分清单一起版本化。先做 Python 与 Swift 同片特征/输出一致性检查，再在手机上旁路推理。[已有实验逐类结果](/Users/hua/Downloads/动作采集分析/14项动作基线-20261123/phase_predictions.csv)

**实验 B：有条件地试轻量 1D CNN。** 等多玩家、成对负例和连续两拍数据齐备，给 CNN 与 SVM 完全相同的手机六轴窗口、标签、分组和反馈时限。首轮可用两个小型时序卷积块提取局部加速与制动顺序，分别训练检测头和专项分类头；早停依据验证玩家的指标。所有增广都在切分后进行。只有当它在封存玩家上减少转腕误触、保住短发/放网召回，并在 iPhone 上满足延迟预算，才进入候选发布版本。原研究的最高分来自其二维卷积架构；这里的轻量一维模型是针对端侧的新实验。

**发布检查。** 用同一段连续流逐帧跑旧版、SVM 和候选 CNN，按人工触球区间一对一匹配。漏掉的真挥记漏拍，一个真挥多触发记重复，无对应真挥记误触；分类同时报告“已检出的拍”与“全部真拍”的结果，避免过滤困难动作后分数虚高。按玩家输出计数、误触/分钟、轻动作召回、连续第二拍召回、14 类混淆、弃权率、从允许触球区间至输出的延迟分布。训练实战样本时只使用复核过的标签。优先选择在同等轻动作召回下误触更少的模型；若无稳定收益，继续保留现有基线并补录具体失败场景。

## 在电脑上模拟手机

先用真实记录重放验证训练和 iPhone 提取的输入一致。再在有三维姿态轨迹的持拍手上挂虚拟手机，设置手到手机的固定变换和握点偏移。由连续四元数相对旋转求手机坐标系三轴角速度；由手机位置二阶差分求世界线加速度，旋转入手机轴并换算成 g，分别生成 userAcceleration、gravity 和 attitude。用静止、单轴匀速旋转和已知直线加速检验符号、单位与时间戳。单目二维腕点不足以确定这一整套三维轨迹。首批合成先从已标真实拍做物理一致的换握与节奏扰动。

按实测范围随机化朝向、速度、噪声、采样抖动、丢帧和持机偏移；标记 synthetic、源动作 ID、种子、参数。冻结真人留出集，只在训练集加入模拟，比较“仅真人”和“真人加模拟”。当轻动作召回或背景误触变差，回退该类合成分布。游戏接球奖励可用于训练虚拟对手；人的主挥瞬间和动作意图需要视频与传感器监督。

## 三个可借鉴的公开方案

- 羽毛球 IMU 开源研究提供 8 类、9,784 条标注挥拍，比较传统分类器与 CNN，并考虑真实击球与假挥。可借鉴分段和模型对照，球拍安装位置与手持手机有域差。[原项目](https://github.com/PhusNguyen/Realtime-IMU-Badminton-Stroke-Recognition)
- Deep Inertial Poser 从动作捕捉生成合成 IMU，再用真实佩戴数据微调。其全身姿态任务使用六个传感器，本项目可借鉴合成到真实的验证方法。[作者项目](https://dip.is.tue.mpg.de/about.html)
- Microduck 公开强化学习训练环境，适合参考仿真、真机验证和可重复实验的组织方式。这里的主要学习目标是给定传感器序列识别人已做的动作，优先监督式分段与分类。[官方训练仓库](https://github.com/pollen-robotics/microduck_rl)

## 本机训练台与真机闭环（2026-11-23）

打开 [Mac 训练台](http://127.0.0.1:8765)。服务停止后，双击项目 Tools 目录的「打开训练台.command」。环境安装在项目 .venv；重建时使用 Python 3.12 和 Tools/training-requirements.txt。录制保存在 ~/Downloads/动作采集，标注库和各版实验产物在 ~/Downloads/动作采集分析/本地训练台。

1. 在手机自由练习中选择「网前时机」，连接 RallyCapture。让 Mac 机位覆盖持机侧肩、肘、腕及整部手机。用同一来球交替做高点扑、轻托、网带推、低点挑和低点下压。另录原地转腕、只引拍后收手，以及一拍后的自然回位。
2. 在训练台打开「逐拍复核」，选择专项或实战、场次和候选。横轴零点为可调整的手机峰时刻；摄像头短片显示相同事件附近 2.4 秒。只有画面能支持的动作才填写实际动作名。明确的无击球意图动作标「背景」，遮挡或时间对不上标「排除」。漏检可手动输入手机时间并补标。不同人使用不同玩家编号，同一场次由同一个人完成。
3. 「扫描最新采集并训练」会读取新增专项和已复核实战。人工修正覆盖同一候选的任务标签。不同玩家应显式填写留出玩家，单玩家阶段按场次留出。背景单独用于有效挥拍检测。检测器需要训练组和测试组中均有人工确认的正负样本。
4. SVM 用峰前 240 ms 至峰值的六轴信号，以 10 ms 间隔插值。五段各取六轴均值，再加角速度与线加速度模长峰值，共 32 维。跨越 40 ms 采样缺口的窗口跳过。标准化只拟合训练集，RBF 的 C 固定为 1。实验另把训练样本的两组三轴绕同一轴旋转 ±8°，在原始真人留出集上单独评估握姿增强。
5. 每个版本保存训练成员、来源、留出预测、按类指标、排除项和模型。需要测试某版时，把该版本 SwingShadow.json 拷贝到 Clients/iOS/Resources 同名位置，构建并安装 Debug 包。连接 RallyCapture 后，shadow 事件记录模型版本及预测，candidate 记录引擎是否接受，judgment 记录比赛判定，trajectory 记录出球和预计过网情况。按峰时间对齐前两项，可定位轻转腕误触发生在哪一级。
6. 首个真机对照版本用 P01 的 42 拍训练，14 拍留出，SVM 命中 5 拍，宏平均 F1 约 0.30；模拟握姿同样命中 5 拍。上述样本都是任务标签。手机 Swift 端在这 14 拍逐一复现 Python 预测。模型作为开发诊断旁路运行。升级比赛识别前应保留独立玩家的整局录像，统计每分钟误触、真实轻动作漏检、收手重复触发、分类混淆和端到端延迟。单拍分类结果无法给出上述整局指标。
