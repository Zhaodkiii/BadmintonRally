# 晚风球社核心玩法重构

## 玩家体验

一局球围绕「预判来球 → 选打法 → 挥拍 → 看落点 → 回位」展开。玩家用手机控制击球时机、打法、方向和相对发力。角色根据来球自动移到可接球位置，画面提前显示可击球区域和来球高度。第一次玩先握稳手机、完成一次对中，然后由教练喂慢球；个性化模板在后续练习逐步补齐。正式对局使用固定难度规则和发接球区，练习允许扩大接球时间和可达范围。

把操作拆成三个入口：

- **三拍入门**。第一拍教回球时机，第二拍教同一高球打后场或网前，第三拍教面对杀球选择挡网或反抽。模拟对手可以复现同一颗来球。
- **专项馆**。沿用 14 种动作页面，增加带确定来球的练习。动画展示准备、引拍、触球和收拍。分开显示「检测到挥拍」「打成哪种球」「落点是否达标」。单次误判可重试、留注和导出。
- **单打比赛**。接发球、普通回合、接杀有各自的合法击球情境。让高远调后场、吊球调前场、平抽压缩反应时间，电脑根据可达范围和回位状态选择回球。低置信度时按难度和玩家预选处理，并标明结果来源。

图解中的握法、准备姿势、接发球和步法适合用于教学动画。手机姿态反映设备相对方向，单机自动跑位根据球的位置和虚拟角色能力计算。脚步、球拍握法和全身姿势需要画面示范或视频标注。

## 14 种动作的玩法定义

| 阶段 | 专项动作 | 可解释的挥拍意图 | 球路和战术 |
|---|---|---|---|
| 发球 | 正手高远发球 | 侧下向前上方长送 | 高弧线，落对角发球区后部 |
| 发球 | 正手短发球 | 正手准备，轻推短收 | 低越网，落对角前发球线附近 |
| 发球 | 反手短发 | 身前短促轻送 | 低越网，落对角发球区前部 |
| 发球 | 反手偷后场 | 反手短发准备，末段向前上方提速 | 越过接发者，落对角发球区后部 |
| 后场 | 头顶高远 | 高位向前上方送拍 | 高弧线压后场，给自己回位时间 |
| 后场 | 正手扣杀 | 高位加速前下挥 | 陡向下，瞄准中场空当或边线 |
| 后场 | 吊球 | 与高远相似的准备，末段控速前送 | 从后场调到前场，落点短 |
| 网前 | 上挑 | 低位向前上方挥 | 挑至后场，化解低来球压力 |
| 网前 | 网前放网 | 小幅轻送，拍面相对稳定 | 近网短落点，引对手向前 |
| 网前 | 网前推球 | 可推高度短促前送 | 平快穿越到中后场空当 |
| 网前 | 网前扑球 | 高于网带机会球，短促前下点压 | 快速下压到近中场，限制触球高度 |
| 中场 | 平抽 | 胸前快速横向挥 | 平快到对方中后场，压缩反应时间 |
| 接杀 | 接杀挡网 | 短距迎挡、发力低 | 借来球回到对方网前 |
| 接杀 | 接杀反抽 | 来球快时短促快横挥 | 快速平直反击到中后场 |

比赛先按发球、接发和回合阶段约束候选，再按来球高度、站位和可达性评分。「同一颗后场高球」仍允许高远、吊球和扣杀。模型分不开时，练习请玩家重做或选择打法，辅助比赛允许开球前预选或触屏选择；进阶模式保留拒识。接杀反抽和平抽可共享横挥检测，但命中时各自使用球路配置。正反手短发的动作标签独立，落点和规则可以共享。所有主动打法的落点都有直线或斜线选项，横向意图来自校准坐标系的方向及峰前拍面。

## 动作识别引擎

| 输入 | 第一版用途 |
|---|---|
| 陀螺仪三轴和角速度模长 | 分段、主运动方向、角速度峰与随挥反向运动 |
| 去重力加速度三轴 | 识别短推、轻挡的前送和制动；与角速度合成相对发力 |
| 姿态四元数与重力 | 建立准备姿态参考，区分向上、向前和向下，映射虚拟拍面 |
| 时间戳和连续序列 | 比较引拍时长、上升沿、峰值、制动、回位和第二拍，检测断流 |

请求约 100 Hz，使用实测时间戳。原始帧留档，按准备姿态变换，做左右手方向映射和因果平滑。姿态用相对四元数，并处理四元数符号连续。用户加速度已经去掉重力。力度是同动作内按个人范围归一化的互动参数，手机不能直接给出真实拍头速度、接触力或全场三维位置。[Apple Core Motion](https://developer.apple.com/documentation/coremotion/getting-processed-device-motion-data)

检测状态为「待机 → 候选 → 主挥确认 → 随挥恢复」。候选同时看角速度、加速度和短时间能量，用静止噪声调整触发门槛。下一拍依据能量回落及新的有向加速重新就位，保留收拍反例、连续正反手和轻挡样本。分段输出挥拍 ID、开始、估计击球时刻、决策时刻、方向、拍面、相对力量和质量；同一事件只可提交一次。高置信度可先确定击球，随挥结束后更新诊断数据。

用「动作族 → 组内分类 → 场景约束」处理 14 类。可先比较特征线性模型与多原型，再测试小型因果时序模型。保留 top-k、相似度差和拒识原因；比赛场景只限制可行结果。采集数据包括两天以上的多人多握姿、左右手、两档速度、专项空挥、同球不同打法以及真实回合。先人工确认逐拍标签，按玩家留出，评估连续输入。当前平均曲线作为对照，近期 14 场留出中仅 3 场匹配提示，不能代表 14 类比赛表现。

## 击球与羽毛球物理

**判球和飞行使用同一时钟。** 单调时间记录传感器样本和判定，固定步长推进比赛。维护短时模拟状态，按估计触球时刻查球、虚拟拍和支撑位；投屏补偿在输入与展示时钟映射中处理一次。以预测接触点的可达区生成提示和判球窗口，练习把区间拓宽。一次早挥可记录为未中并允许另一独立候选继续接同一颗球，直到触球窗口结束。晚挥、场景不允许、角色未到位、识别不确定各有独立原因。

**命中后从接触点出球。** 给 14 种打法定义可接高度、初速度、仰俯角、力度范围和目标区域。命中质量来自时机、拍面与可达裕量；方向映射到目标区，力量改变速度与深度。用重力和约随速度平方增长的阻力积分轨迹，验证越网、场线、落地和发球对角区。落点与速度物理可兼容时再选初始条件，擦网、下网、出界由轨迹决定。高远、吊球、平抽、杀球、挑球建立同场景可重复的轨迹夹具。[羽毛球空气动力学研究](https://doi.org/10.1088/1367-2630/17/6/063001)

**电脑按站位追球。** 从可接触的预测点选路线，难度调反应时间、移动速度、到位后可选的打法和击球误差。随机因素使用可记录的种子。关键测试是先挑深区、再吊前场时，得分变化能由对手回位和实际可达性解释。

## 3D 呈现

建议用 RealityKit 做固定球场视角的原生 3D，首个原型选择与目标系统兼容的非 AR 视图。SwiftUI 放菜单和比赛 HUD，Swift 模拟保持独立。渲染从模拟快照插值，使用米制球场和统一坐标，挂载球网、羽毛球、角色骨骼、虚拟球拍、地面球影、落点标记和短尾迹。动画在实际接触帧对齐击球，移动和击球分别过渡。第一版用简单模型验证球路和视角，优先比较手机端与电视镜像的低球可见度、出球延迟和稳定帧率。[Apple RealityKit](https://developer.apple.com/documentation/realitykit)

## RallyCapture 实时调试

已接入第一版比赛实时传输。iPhone Debug 版在「动作测试」与 RallyCapture 配对后，在设置中打开「实时发送比赛诊断到测试 Mac」，再开始一局。使用原有可信连接。Mac 在「动作测试接收」显示比分、收到的帧数、检测到的缺批和比赛文件入口，每局写一个 JSONL。应用支持持续显示诊断，并从文件读取任意时间段进行开发分析。

| 同一批里的数据 | 用途 |
|---|---|
| 手机单调时间、比赛时钟、比赛 UUID、批次号 | 对齐运动、判球和快照，识别传输空洞 |
| 三轴角速度、三轴用户加速度、重力、姿态四元数 | 回看实际挥拍，复查检测门槛和握姿 |
| 识别候选、峰值、输出时刻、曲线类别和相似度 | 区分未检出、候选拒绝和分类混淆 |
| 判球结果、挥拍种类、瞄准量、匹配的游戏时间 | 找出挥早、挥晚、锁定、发球不符和离球太远 |
| 比分、阶段、双方站位、球路、数字补偿与击球窗 | 重建失败场景，检查画面与操作判定 |

第一版约每 100 ms 发一批，Mac 保存后确认；前一批未确认时允许跳过后续批次，保留序号供查缺。当前直播记录用于查问题，完整离线重放仍需增加手机持久化、补传、比赛随机种子与完整输入日志。后续 Mac 增加「挥拍 → 识别 → 判球 → 球路」逐帧时间线及确认标签。开发构建默认关闭实时发送，正式构建没有发送入口。

## 实施与验收

| 阶段 | 本期交付 | 验收 |
|---|---|---|
| ① 建立基线 | 当前比赛判球原因、动作流和球路同时到 Mac | 试打一分，能对上候选峰时间、输出、判球原因和对应来球 |
| ② 重写回合核心 | 固定步长、接触区、统一投屏时间、可重放发球与回位、确定性对手 | 测试同一输入重放相同得分；挥早后在同一来球有效补挥；投屏提示与判球边界一致 |
| ③ 物理与战术 | 先实现后场高远、吊球、扣杀、网前挑球、平抽五种已定球路，再接入其余九种配置 | 同一次来球能主动打出不同落点，网高、界内和发球区规则可由轨迹测试 |
| ④ 14 类动作引擎 | 新检测器、场景候选、端侧模型与逐击诊断 | 留出玩家上分别统计漏检、误触、连续第二拍、各类混淆和出球延迟 |
| ⑤ 3D 与投屏 | 独立渲染、统一相机、教学与比赛动画对齐 | 比较第一拍成功耗时、连续回合长度、投屏挥动至画面出球延迟、两类战术选择命中率 |

## 原始参考项目

- 手机上的挥拍输入映射到球路和击球参数可参考 [Physics-Based Table Tennis](https://github.com/maratlee1031/Physics-Based-Table-Tennis-Simulation-and-Trajectory-Prediction-with-Smartphone-Motion-Control)。其中的视觉追踪与拍球参数属于该原型的输入条件。
- 手机姿态映射到 3D 持拍角色可参考 [TennisGame](https://github.com/utkualkan4112/TennisGame)。
- 挥拍峰值仪表和硬件采集可参考 [Badminton Tracker](https://github.com/JustinwkWan/badminton-tracker-app)。其采集设备为外置 IMU。
- 以静止和背景作为独立类的轻量分类可参考 [TinyML Smart Tennis Sensor](https://github.com/alvarowolfx/tinyml-smart-tennis-sensor)。
- 原生传感器到画面的低开销输入可参考 [GyroGame](https://github.com/brenici/gyrogame)。
- 局域网传感器流的组织可参考 [MotionBridge](https://github.com/bipinmaurya5567-bit/MotionBridge-Control-PC-Games-with-Your-Smartphone-Sensors)。本项目沿用 RallyCapture 已配对的传输链路。
