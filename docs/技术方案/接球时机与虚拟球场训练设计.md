# BadmintonRally 接球时机与虚拟球场训练设计

本方案面向 iPhone 游戏与 Mac 开发工作台。先做一块可以重复喂球、回放真人挥拍的单打球场，让同一套击球逻辑驱动手机比赛和 Mac 实验。首轮目标是让玩家能解释一拍为什么没碰到、为什么打浅，以及下一拍可以怎么调整。

## 1. 先解决实战暴露的问题

11 月 23 日的 DAD3421B 场次中，46 次接受输入有 43 次标记为“基础回球”。将这些事件与同批或随后最近的球路快照对齐，得到 38 次机会球、4 次放网、1 次平抽。现有 Rally.swing 会先尝试专项曲线与情境匹配，再处理方向未定的输入；当前日志中的基础回球表示输入路径。引擎把大量方向未定的挥拍处理成机会球，使熟练玩家即使及时接到，也很难通过挥法改变局势。

新增独立的逐拍记录字段：候选拍 ID、来球 ID、主挥区间、估计触球时刻、分类完成时刻、候选打法及分数、角色可达距离、球拍接触位置、实际出球类型、出球速度与方向、过网余量和最终落点。时间戳保留手机单调时钟及对应仿真步。分析页把“方向难分”“角色赶不到”“出球下网”分别显示。多人难分的同类手势可共享动作族，保留专业标签供训练。

## 2. 同一来球应允许怎样打

| 固定喂球 | 玩家在什么位置做什么 | 预期反馈和结果 |
| --- | --- | --- |
| 网前略高于网带的慢球 | 提前举拍，在身体前方高点短促下压 | 扑球，初速快、下降明显；短挥即可完成 |
| 同一球下降到网带附近 | 身前短引、平顺前推 | 推球，较平地越网，进入中场；轻托则允许放网 |
| 同一球继续降到网带以下 | 向前上方挑，角色仍够得到 | 挑球，高弧线；力量不足落中场。此时坚持向下压，若触球且球路撞网则下网 |
| 后场高球 | 角色到位，球在持拍肩前上方；分别向前上、向前下、减速轻送 | 高远、扣杀或吊球。三种选择可共享一段可接时间，让玩家选择战术 |
| 后场同一球已越过肩部 | 角色转身勉强够到，仍尝试强扣 | 有接触时，受限于触点和挥向，扣球角度变平或回球偏短；超出伸手范围则挥空 |
| 对手杀球 | 身前稳住拍面短挡，或在身前快速平挥 | 前者借来球速度挡网，后者反抽；来球快时缩小所需引拍幅度。挥拍峰出现得早，但球尚未到拍面，判挥空 |

时间窗口由球进入和离开当前动作可达区域的时刻决定。相同的“晚 100 毫秒”，对慢高球可能只是触点略低，对快速杀球可能已经错过整段接触机会。前后场高度、左右持拍和角色移动都会改变这个区间。

## 3. 从手机动作到一次可解释的碰撞

1. 保留约一秒的 IMU、球和人物姿态历史。沿用个人握姿校准，对齐陀螺仪方向，提取引拍方向变化、主挥积分转角、角速峰、前送加速度、减速形态。紧凑短打允许小引拍，通过有方向的前送和制动与连续抖动区分。
2. 识别器输出挥拍族、连续力度、方向、置信度及主挥有效区间。短挡、短发等分别与自己的样本比较。识别置信度决定动作族候选；回球质量由接触现场计算。两者各自可回放调参。
3. 将挥拍族绑定到角色身上的参数化球拍轨迹。按时间在主挥段扫过拍面，并与同一时段的羽毛球线段做连续碰撞，避免快球在两帧之间穿过去。追溯范围受当前来球 ID、过网和首次落地事件约束；同一挥拍对同一来球只结算一次。网络显示补偿与识别等待单独记录。
4. 在可达范围内，求接触点离理想甜区、理想伸展和理想触球位置的偏差。边缘接触逐渐降低方向控制和能量传递。拍面方向与相对速度决定出射方向；同一拍重放得到同一球路。实机首版以个人校准和动作族估算虚拟拍面，手机无法给出真人拍头或手腕的绝对空间位置。
5. 未相交就让来球继续飞；触球后先生成初始速度，再判断球实际过网、触网和落点。首次碰网按碰撞后的速度处理，擦网继续越过可继续比赛。每拍只显示一个原因，如“球已过肩”“低点击球，拍面朝下”。详情留给 Mac。

## 4. 14 种动作与动画资产

| 动作 | 动画、球路和情境参数 |
| --- | --- |
| 正手高远、正手扣杀、吊球 | 共用后场侧身准备。高远向前上方充分伸展；扣杀高点向前下方通过；吊球保留前段引拍，在触球附近收力。分别标注触球帧及后续收拍方向。 |
| 正手挑球、网前放网、网前推球、网前扑球 | 共用跨步到网前。挑球从低处上送；放网短托且拍面稳定；推球向前穿过；扑球在网带上方下压。触点高度由世界状态提供。 |
| 平抽、接杀挡网、接杀反抽 | 共用身前准备。平抽横向快速挥出；挡网小幅承接、减速；反抽遇到快来球仍主动加速向前。为短挡专门采集自然收手负样本。 |
| 正手高远发球、正手短发、反手短发、反手偷后场 | 只在发球阶段候选。正手两种比较挥幅与发力方向；反手两种共用准备姿态，比较触球前的加速和上送。分别验证斜对角前区、后区落点。 |

每段动画标准备、引拍结束、主挥开始、接触、随挥结束、恢复可接球六个标记。人物移动先判断能否赶到；进入可达区才用手臂逆运动学校正持拍手与触点，限制肩肘伸展、脚底滑动及校正距离。盲目伸长手臂会把真正的挥空画成击中。音效、震动和球路切换读取统一接触事件，错拍播放完整挥空及恢复动画。

## 5. 虚拟训练场怎样搭建

- **共享仿真核心**。从 Rally 中提取独立于 SwiftUI 的世界步进。球场统一用米和秒，明确朝上、过网、横向三轴；固定步长初选 1/120 秒，渲染插值。首版以重力加与速度平方相关的阻力模拟减速，用可配置的出射速度、仰角和方位角生成球路。用有已知尺度的真实打球录像校准飞行时间、最高点、过网高度和落点。现有空挥录像可校准动作时序，不能标定真实羽毛球的空气阻力。
- **可复现实验**。每次保存规则、模型、校准、动画版本、随机种子、初始球与人物状态、逐帧输入。Mac 可以固定同一来球，把同一真人主挥前后移动，或只改变角色站位、挥向、力度。旧比赛受随机 AI 和历史版本影响，先回放到首次判定分歧；之后分支仿真，分别记录结果。
- **玩家训练**。先看一次喂球 → 自动归位 → 连续打同一球五次 → 每拍显示触点和结果 → 查看最佳一拍与失误一拍。提供“再打同一球”和“换下一种来球”。首轮只开放网前机会球、后场高球、接杀三站，每站安排一种来球两种打法，测试玩家能否主动控制结果。
- **Mac 标注与模型训练**。同屏联动摄像头、游戏录像、IMU 和球拍扫过的区域。用本场 43 次基础回球和约 13 次可接时段的引拍拒绝作为待复核队列，重合样本按拍去重。标注意图、实际动作族、引拍/主挥/随挥边界、虚拟触球允许区间及“看不清”。保留等待、调握、抖动、只引拍、单拍后收手和连续两拍。模型以多玩家真人标签为主，按玩家和场次分割；虚拟世界主要训练时机策略、生成碰撞边界案例、校验动画。增强后的曲线跟随原场次划分。
- **记录启动**。开发采集模式中先启动视频和摄像头，记录各自首帧时间，再发第一球。摄像头不可用时允许继续，并把覆盖缺口显示在场次里。这能处理最近一局开场约 5.7 秒没有游戏录像的问题。

## 6. 交付顺序和验收

| 阶段 | 可直接验收的交付 |
| --- | --- |
| 第一轮：打通一条球 | 固定网前同一来球；支持高点扑、网带平推、低点挑、低点下压触网及挥空。Mac 叠画球、拍面和接触点。检查提前、理想、偏晚、完全错过四种轨迹，不以随机概率代替碰撞。 |
| 第二轮：扩到三站 | 增加后场与接杀。触屏脚本先隔离物理，随后接入个人 IMU、动画接触标记和录像。对每条固定输入重复运行 100 次，逐拍事件及落点应在既定浮点容差内一致。 |
| 第三轮：真人训练与扩类 | 复核难例后实现 14 类的条件映射，留出未参与训练的玩家。对同一批回放比较有效小动作漏检、等待时每分钟误触、重复出球、不同打法混淆矩阵、触球到反馈的中位数及 P95。灰度真机比较原版与新版。 |
| 发布判断 | 让新玩家对同一种来球交替指定两种合理打法，统计意图命中率，并单独报告合法弱回球和真正挥空。只有当意图命中改善、误触和反馈延迟没有明显恶化，才将新规则设为默认。首轮先采基线，再与团队确定数值门槛。 |

## 已接入游戏的网前时机练习（2026-11-23）

入口为「自由练习 → 练习内容 → 网前时机」。喂球落点和飞行时长固定，可连续比较同一来球。比赛与练习共用 Rally.swing 和 Flight。传感器判定到达时按估计击球时刻回看来球和角色位置。球仍在对面会挥空并收拍；球过网后以角色位置和挥幅近似可触达区域。高点下压出快球，轻托或预选放网出短球；贴网平推的深度随伸拍余量减小，回浅时对手抢到球可下压；低位上挑的深度随力度增加；低位下压碰球后继续飞到网前，轨迹触网时判失分。球超出触达区时保持原来球。

Tests/Checks/RulesChecks.swift 的 checkNetTiming 用同一条喂球轨迹验证提前挥、收拍锁定、高点两种选择、伸拍推浅、低点轻重挑、下网判分和扫空。当前可触达区域使用虚拟人物与挥动幅度估计，未测量真实拍面三维位置。场地和高度采用现有引擎的归一化坐标。带空气阻力的米制飞行与真实人体骨架仍属于后续验证范围。
